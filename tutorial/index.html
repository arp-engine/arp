arp 引擎使用教程

面向「数据驱动 + 组件化」的 C++17 风格化渲染引擎。本教程以 games/world_of_claudecraft 项目为参考实例，讲解 arp 引擎的十大核心系统：渲染管线、GameObject+Component 运行时框架、动画、粒子、UI、资源管理、反射、网络、Shader、预制体；并附一篇资产导入参考。

所有 API 名称、字段、枚举值均直接取自引擎源码（src/）与项目状态文档（docs/），可作为权威参考。文中代码片段为真实接口签名，未经臆造。

引擎与项目的关系

arp 引擎的核心代码位于仓库根 D:\arp-engine\src\，分为若干后端中立（backend-neutral）的子系统；具体游戏（如本教程的参考项目 games/world_of_claudecraft）在引擎之上做游戏逻辑与内容适配，并通过 DLL 链接到 arp_engine。

本教程的「参考实例」指的就是中间的 world_of_claudecraft：它用引擎的 GameObject/Component 搭建场景，用 animation 命名空间做动画，用 arp::renderer::ParticleSystem 做特效，用 arp::ui 做 HUD。下面每个系统都会给出「引擎接口 → 项目里怎么用」的对照。

构建与运行

引擎使用 CMake，首选 MinGW + Ninja，Windows 上通过 scripts/build.ps1 即可构建；着色器通过 scripts/compile-shaders.ps1 离线编译为 SPIR-V / MSL（slangc）。

# 本地（MinGW）一键构建 + 着色器
.\scripts\build.ps1

# 或直接用 CMake preset
cmake --preset ninja-mingw-debug
cmake --build --preset ninja-mingw-debug
ctest --preset ninja-mingw-debug

# 离线编译着色器（Slang → SPIR-V / MSL）
.\scripts\compile-shaders.ps1

运行示例（无窗口模式，适合 CI）：

# 风格化展示（隐藏窗口，跑 2 帧）
.\artifacts\cmake\ninja-mingw-debug\arp_stylized_showcase.exe --hidden --frames 2

# 全功能特性演示（Esc 或关窗退出）
.\artifacts\cmake\ninja-mingw-debug\arp_stylized_showcase.exe --feature-demo

# 生产级 demo（1280x720 Vulkan 窗口）
.\artifacts\direct\arp_production_demo.exe

参考项目如何构建：world_of_claudecraft 作为引擎的一个游戏目标参与整体构建，链接到 arp_engine。具体可执行文件名以仓库 CMake 配置为准；游戏逻辑改动通常无需重编引擎本体。

术语表

GameObject
场景中的对象节点，拥有 id、名称、父子层级、active 状态与 TransformComponent；组件挂载其上。
Component
挂在 GameObject 上的可复用行为/数据单元，含 onUpdate/onLateUpdate 生命周期与 extract() 渲染提取钩子。
RenderQueue
提取阶段产出的「渲染项 + 队列记录」，携带句柄、元数据、世界变换、包围盒与排序键，不含原生顶点拷贝。
FrameGraph
帧级 pass 依赖与资源规划器；compile() 产出 CompiledFrameGraph（顺序、生命周期、barrier、别名、load/store、队列）。
DrawPlan
渲染器拥有的「绘制计划」，含 submesh/材质 push-constant 与 GUI 文本/四边形绘制命令顺序，经 RHI 编码器录制。
RHI
渲染硬件接口第 2 版，L2 命令录制契约；原生 Vulkan/Metal/WebGPU 实现藏在 backend 私有目录。
Backend-neutral
后端中立约束：scene/renderer/render_graph/ui 不得 include 原生图形/平台头或暴露原生句柄。
pmr 分配器
运行时动态容器统一使用 core::pmr（core::makeUnique/makeShared），禁止默认 STL 动态分配进入热路径。
ResourceManager
引擎唯一的运行时资源注册/缓存中心；资源以类型化 ResourceBase 子类接入，经 load/find/findByAlias 与 ResourceHandle<T> 类型化查询，靠内容指纹支持确定性重载。
Slang
arp 的统一着色语言；一份 .slang 源码经 slangc 编译为 SPIR-V / MSL / WGSL 三目标，uniform/cbuffer 按 std140 打包。
Push constant
每帧直推 GPU 的小块常量（如 view-projection、材质参数）；arp 约定结构体按 std140 对齐、总大小 ≤ 256 字节，并由 RHI 两层校验保证与着色器反射一致。
Prefab（预制体）
资产侧的可复用模板，描述 GameObject + Component + 子层级；实例进入场景后变为 SceneObject（见 02）。引擎以 PrefabResource 为引用图枢纽，按 UUID 引用同一内部资产包里的模型、蒙皮、骨骼、动画、材质、运行时负载等资源。
内部资源
引擎统一建模的资产单元，由 ResourceManager 与内部资产包（ArpInternalAssetPackage/v1）管理；当前共 21 个类型（见 10），与项目级 ContentAssetResource（06）共用同一套生命周期/句柄/契约模型。
资产导入
DCC 工具导出的磁盘源格式（如 .glb/.fbx/.png/.mat/.slang）经 importer 转成内部资源包；权威扩展名→类型映射见 assetTypeForExtension()（11）。
