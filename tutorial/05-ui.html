05 UI Prototype Complete

arp 引擎的 UI 系统（src/ui，屏幕空间；src/gui 为 retained GUI 树与 flex-like 子集）是一个后端中立、确定性布局与命中的框架。屏幕空间 UI 是显式的 Canvas + Widget 树（不是 GameObject 层级，也不需要相机）；世界空间 UI 通过「锚点桥 + 解析相机」投影到屏幕矩形。

核心概念

1. Canvas 与 Widget

Canvas 是根容器，携带视口、安全区、缩放策略与最大控件数；Widget 通过 createWidget(WidgetDesc) 创建并挂到父节点。resolveLayout() 产出 ResolvedWidget 列表，hitTest() 做确定性命中测试。UI 树明确不暴露原生后端句柄、不在热路径生成静态顶点数据。

Canvas canvas("hud", {
  .viewport = UiViewport::explicitPixels(1280, 720),
  .safeArea = UiSafeArea::none(),
  .scalePolicy = UiScalePolicy::fixed(1.0f),
  .maxWidgetCount = 1024,
});

Widget& root = canvas.createWidget({ .name = "root" });
Widget& panel = canvas.createWidget({ .name = "panel",
  .localRect = { 24, 24, 360, 96 }, .controlType = UiControlType::Panel });
canvas.reparent(panel.id(), root.id());

auto layout = canvas.resolveLayout();   // CanvasLayoutResult

2. 布局引擎

LayoutEngine 是静态解析工具：按 Style（fixed/percent/min/max、stretch、padding、gap、axis、align）解析宽高与对齐原点。支持 Stack / Grid 布局参与模式。

Style s;
s.axis = Axis::Column;
s.align = Align::Start;
s.fixedSize = { 200, 0 };
s.padding = Spacing::all(8.0f);

float w = LayoutEngine::resolveWidth(s, parentWidth);
float x = LayoutEngine::alignedOrigin(s.align, origin, content, child);

3. 控件与交互

UI 提供一套控件类型（Panel/Label/Button/Slider/Checkbox/TextInput/Dropdown/Tabs/TreeView/ColorPicker/Image/ScrollView…），每个控件是薄封装，暴露确定性交互方法（如 Button::click、Slider::drag、Dropdown::select）。UiControlRuntime 管理控件集合、焦点捕获与交互分发；InputRouter 在游戏输入之前消费指针/键盘/文本，返回 InputConsumption 以避免 UI 输入再去驱动角色。

UiControlRuntime ui("hud", canvasDesc);
auto btn = ui.createControl({ .type = UiControlType::Button,
                              .widget = panelWidgetDesc }, rootId);
ui.interact(UiControlInteraction::click(btn.widgetId()));

// UI 先于游戏输入消费；被消费的指针不再驱动玩家
InputRouter router;
auto route = router.route(canvas, layout, inputSystem);

4. 渲染提取与 DrawPlan

提取阶段把布局结果转为 UIRenderItem（Box/Text/Image），写入 RenderQueue（不含原生句柄/静态顶点），再由 DrawPlanner::plan() 产出 DrawPlan（含排序键 zOrder），最终经渲染器/RHI 绘制。引擎通过 DocumentComponent（挂在 GameObject 上的 arp::ui::DocumentComponent）把 .arpui 文档挂载到运行时。

RenderExtractor extractor;
auto rq = extractor.extract(canvas, layout);   // UIRenderExtractionResult
DrawPlanner planner;
auto plan = planner.plan(rq.queue());       // DrawPlanResult

5. .arpui 资源与创作流程

屏幕 UI 由 .arpui 文件声明（Contract Complete）。运行时、渲染器、RHI、玩法代码只消费显式的 .arpui 元数据。示例 schema 含 canvasId/screenId/viewId/stateId、安全区策略、命令角色、游戏绑定、数据绑定、纹理图集切片与节点树。

{
  "type": "ArpUiDocument",
  "contractVersion": "arpui.v1",
  "canvasId": "pika.hud.canvas",
  "safeAreaPolicy": "RespectPlatformSafeArea",
  "commandRole": "command.pause",
  "gameBinding": "pika.session.pause",
  "dataBinding": "binding.player.health",
  "textures": [ { "resourceId": "ui/pika/hud_bar", "atlas": "pika_ui_atlas", "sliceLeft": 8, "sliceTop": 8 } ],
  "nodes": [ { "id": 1, "parent": 0, "type": "Panel", "style": "hud.panel" } ]
}

禁止回退规则：不靠 layer 名推断语义；不在运行时解析 PSD/Illustrator/Figma/截图；缺失纹理/图集/命令/状态/安全区/数据绑定时必须报确定性诊断（如 MissingRequiredResourceBinding、MissingCommandBinding），不得静默猜测。

6. 世界空间 UI（名称牌/血条）

世界空间 UI 不是把 UI 节点变成场景子物体，而是：场景对象暴露 WorldAnchorComponent 元数据，WorldAnchorProjector 结合稳定遍历快照与 ResolvedCamera 计算屏幕矩形；UI 控件树仍在 src/ui。命中测试、焦点、布局规则与屏幕 UI 一致。

WorldAnchorProjector projector;
auto anchors = projector.project(scene, snapshot, camera, canvas);
// anchors: 每个 WorldAnchorProjection 含 widgetId + 屏幕 LayoutRect

参考实例：world_of_claudecraft 的 HUD

该项目用两类 Component 驱动 HUD：UiTextComponent（文本，typeId wocc.hudtext）与 UiBarComponent（血条/蓝条/经验，typeId wocc.hudbar）。它们在 extract() 中推送矩形 + 内容 + styleId（如 text.hud/bar.hp），由 HUD 画布构建器收集，生成「背景 Box + 填充 Box（宽度 = rect.width * fillRatio）」。presentation::HudPresenter::buildFrame() 则把 Character 的属性（职业/等级/血量/蓝量）排成 HudFrame 元素。

// presentation/hud.cpp — HUD 每帧构建
HudFrame frame = presenter.buildFrame(character, screenW, screenH);
// 元素含职业+等级文本、红色血条、蓝色蓝条、经验百分比

注意区分两条 HUD 路径：① 组件驱动的 wocc.hud* payload → HUD 画布构建器（数据驱动、适合绑定角色属性）；② presentation::HudPresenter 直接由 Character 构建（适合演示/快速原型）。两者都落在 arp::ui 的 DrawPlan 渲染链上。

成熟度

UI 框架能力（Layout / Style / Interaction / Text / Image / ResourceBinding / RenderExtraction / Diagnostics / HotPathConstraints）通过 UiFrameworkContract 声明状态，当前整体为 Prototype Complete；可见窗口/多平台与 Production Ready 尚未声明。.arpui 创作流程为 Contract Complete。

快速上手清单

  1. 用 Canvas + createWidget(WidgetDesc) 建屏幕 UI 树，reparent 组织层级。
  2. 用 Style / LayoutEngine 描述布局，调 resolveLayout() 拿 ResolvedWidget。
  3. 用 UiControlRuntime 管理控件与交互；用 InputRouter 在游戏前消费 UI 输入。
  4. 提取 RenderExtractor::extract → DrawPlanner::plan → 交给渲染器录制。
  5. 世界空间 UI 用 WorldAnchorComponent + WorldAnchorProjector，不要变成场景子物体。
  6. 美术/策划编辑 .arpui，缺失绑定必须报确定性诊断，不要猜测。
