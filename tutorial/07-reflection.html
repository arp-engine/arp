07 反射系统（reflection）

arp 的反射是一套运行时类型系统（位于 src/reflection/），风格接近 pybind11：在程序启动时把类型、属性、方法、枚举登记进一个全局数据库，之后就能用 object 这种「动态值包装」做任何类型的读写、调用、序列化、向下转换。它是 06 资源管理中 YAML 内容（反）序列化、以及编辑器/数据驱动工作流的地基。

状态：Stable 核心类型与注册宏稳定；序列化走 serialize_to_yaml / deserialize_from_yaml，作为资源管线（第 06 章）的内容指纹与确定性重载的输入。

7.1 它解决什么问题

没有反射时，渲染/资源/UI 各系统只能硬编码它们认识的数据结构，难以做到：

  • 数据驱动：把 content/*.yaml 反序列化成任意注册的 C++ 对象（见 06）。
  • 通用序列化：用一套 YAML 编解码覆盖所有 class_info 类型，而非每种类型各写一遍。
  • 编辑器/工具：在不知道具体类型的情况下枚举属性、读写数值、调用方法。
  • 跨系统对象传递：用 object 在脚本、资源、动画状态机之间搬运值。

7.2 核心类型

反射系统由一组协作的类构成，全部位于命名空间 arp::reflection：

类型角色关键成员
class_info一个被登记类型的元信息is_base_of / is_derived_from / up_cast / dynamic_cast_ / new_object / call / def_property / inherit
typeinfo类型特征位掩码（是否 class/enum/pointer/wrapper/容器…）is_class() / is_pointer() / is_wrapper() / class_()
object动态值包装（类似 pybind11 object）is<T>() / cast<T>() / ptr<T>() / call(name, args) / operator[]
variant类型擦除的值存储（object 内部持有）is<T>() / cast<T>() / type()
function可反射调用的可调用对象call(args) / set_default_arguments / is_static()
property属性描述符（getter/setter/间接指针）get_value / set_value / is_readonly / has_indirect_value
enumeration枚举反射（名字↔值映射）get_enum_value(name)
db全局反射数据库单例db::instance() / find_class(name) / register_class(...)

value_t 枚举描述了值的可能形态：undefined_t / null_t / boolean_t / integer_t / float_t / string_t / list_t / instance_t / dict_t / buffer_t / function_t / class_t / property_t / enumeration_t / others_t。variant 和 object 都会携带这个标记。

7.3 注册一个类型

用 registration::class_<C> 构建器把类型登记进数据库。链式调用描述构造函数、属性、方法、继承与枚举：

#include "reflection/reflection.h"
using namespace arp::reflection;

struct Vec3 { float x = 0, y = 0, z = 0; };

struct CombatComponent {
    int  attack = 10;
    float critChance = 0.15f;
    Vec3 aimOffset;

    int computeDamage(int base) const { return base + attack; }
};

void registerCombatComponent() {
    registration::class_<Vec3>("Vec3")
        .construct<>()
        .property("x", &Vec3::x, "X 分量")
        .property("y", &Vec3::y, "Y 分量")
        .property("z", &Vec3::z, "Z 分量");

    registration::class_<CombatComponent>("CombatComponent")
        .construct<>()
        .property("attack", &CombatComponent::attack, "攻击力")
        .property("critChance", &CombatComponent::critChance, "暴击率")
        .property("aimOffset", &CombatComponent::aimOffset, "瞄准偏移")
        .method("computeDamage", &CombatComponent::computeDamage)
        .constant("kMaxAttack", {
            enum_value("Low", 1),
            enum_value("High", 999),
        });
}

构建器方法一览：

方法作用
.def(name, object)登记一个静态字段/属性（任意 object 值）
.def_property(name, type, getter, setter, doc, hints)底层属性钩子（带 doc/hints）
.property(name, &C::member, doc, hints)反射一个成员变量（自动生成 getter/setter；指针/智能指针成员生成间接值）
.method(name, func, defaults...)反射一个成员或自由函数，可带默认参数
.construct<Args...>()登记构造函数（生成 __new__/__init__）
.destruct()登记析构
.constant(name, enum_values)反射一个枚举（用 enum_value(name, value) 列表）
.inherit<B>()登记基类并安装 upcast 函数，支撑运行时向下转换

7.4 运行时类型识别（RTTI）

要让一个多态基类能「找回派生类类型」，在类里注入 RTTI 钩子即可（宏来自 reflection_macros.h）：

#include "reflection/reflection.h"
#include "reflection/reflection_macros.h"

struct Component {
    AGENERATED_BODY(Component)          // 展开为 OBJECT_RTTI_IMPL + friend
    virtual ~Component() = default;
};

struct CombatComponent : Component {
    AGENERATED_BODY(CombatComponent)
};

AGENERATED_BODY(TypeName) 展开为 OBJECT_RTTI_IMPL(TypeName)（即 ARP_REFLECTION_OBJECT_RTTI_IMPL），它会覆写 get_ptr() 与 get_derived_info()，后者返回 {this, class_of_instance(this)}。这样从基类指针就能拿到真实派生类型的 class_info。

7.5 用 object 读写与调用

object 是类型擦除的值包装，可以从任意 T 构造，再安全地 cast 回去：

// 构造一个反射对象
CombatComponent c;
object o = object(&c);                       // 包住指针

// 读属性
int atk = o["attack"].cast<int>();           // 10
float crit = o["critChance"].cast<float>();  // 0.15f

// 写属性
o["attack"] = object(42);                     // 通过 property setter
int now = o["attack"].cast<int>();            // 42

// 调用方法
object dmg = o.call("computeDamage", object(20));
int result = dmg.cast<int>();                 // 62

// 类型判断与向下转换
if (o.is_derived_from(class_of<Component>())) {
    Component* base = o.cast<Component*>();   // 安全基类指针
}

向下转换走 class_info::dynamic_cast_(dst, ptr)，依赖 .inherit<B>() 安装的 upcast 函数链；object::can_safe_cast<T>() 在转换前做类型安全预检。

7.6 序列化：YAML 双向

反射直接服务于 06 资源管理 的内容加载——资源系统在反序列化 YAML 时调用下面两个函数，把文本转成 object、再转成具体 C++ 类型，并据此计算内容指纹。

#include "reflection/serialization.h"

// 对象 → YAML 文本
CombatComponent c; c.attack = 42;
object o = object(&c);
ReflectionYamlResult out = serialize_to_yaml(o);
if (out.success) {
    core::pmr::String yaml = out.yaml;        // 例如 attack: 42\ncritChance: 0.15\n...
}

// YAML 文本 → 对象（需先按类型名登记）
ReflectionObjectResult in = deserialize_from_yaml(R"(
CombatComponent:
  attack: 42
  critChance: 0.15
)");
if (in.success) {
    CombatComponent* cc = in.value.cast<CombatComponent*>();
}
确定性提示：ReflectionYamlResult.diagnostics 与 ReflectionObjectResult.diagnostics 在失败时给出定位信息。资源系统在重载时对比序列化结果的内容指纹（见 06 的 appendContentFingerprint），所以反射序列化顺序必须是确定的——同一次数据的 YAML 输出不应随进程状态变化。

7.7 参考实例：与资源管线的衔接

回到 games/world_of_claudecraft 的视角：第 06 章的 ContentAssetResource 在 load() 阶段解析 content/*.yaml，而 YAML 文本到运行时对象的转换正是由 deserialize_from_yaml 完成的。一个内容文件之所以能被反序列化成 CreatureDef/ItemDef 之类的结构体，前提是这些结构体已经在启动时通过 registration::class_ 登记过。

因此典型的内容驱动流程是：

  1. 启动时调用各模块的 registerXxx()（如 registerCombatComponent()），填充反射数据库；
  2. 资源系统声明并加载 YAML 内容资源；
  3. deserialize_from_yaml 把文本映射成 object，再 cast 成具体类型；
  4. 运行时通过 object 读写属性，或交给渲染/动画/UI 系统消费。

7.8 反射代码生成（arp_reflect_codegen）

手写 registration::class_<C>（见 7.3）对每个字段/方法都要写一行，类型一多就很啰嗦。引擎提供 codegen 工具：在头文件里用标记注释标出要反射的类型与成员，构建期由 CMake 自动扫描这些头文件，生成一份 .reflection.gen.cpp——而它内部调用的，就是和手写完全相同的 registration::class_<C>() API。

标记语法

在类型或成员正上方一行写标记（工具是轻量行扫描器，靠「标记行 + 下一非空行的声明」配对）：

标记作用紧跟的声明
ACLASS反射一个 classclass 定义
ASTRUCT反射一个 structstruct 定义
AENUM反射一个 enum classenum class 定义
APROP反射一个公有字段成员变量的声明（含 ;）
AFUNC反射一个公有方法成员函数声明（含 ()）

标记可带括号体：(Name="...") 覆盖反射名；(Construct Default) 生成默认构造函数；还可写逗号分隔的 flag（目前仅记录）。字段/方法必须紧跟在标记下一行。

// my_types.h
#include "reflection/reflection.h"

ASTRUCT(Name="Transform")
struct Transform {
    APROP float x = 0;
    APROP float y = 0;
    APROP float z = 0;

    AFUNC
    float length() const;
};

AENUM(Name="Axis")
enum class Axis {
    X, Y, Z
};

生成的产物

工具为每个 --module 产出两份文件（--out-cpp 与 --out-json）：

  • <module>.reflection.gen.cpp：放在 namespace arp::reflection::generated，导出一个 register_<module>_reflection() 函数，内部用 registration::class_<T> 登记——等价于手写。例如引擎自带的 core_math 模块生成：
// Generated by arp_reflect_codegen. Do not edit.
#include "src/core/math.h"
#include "reflection/reflection.h"

namespace arp::reflection::generated {

void register_core_math_reflection()
{
    using namespace ::arp::reflection;
    {
        auto cls = registration::class_<arp::core::Vec3>("Vec3");
        cls.construct<>();
        cls.property("x", &arp::core::Vec3::x, "", 0);
        cls.property("y", &arp::core::Vec3::y, "", 0);
        cls.property("z", &arp::core::Vec3::z, "", 0);
    }
}

} // namespace arp::reflection::generated
  • <module>.reflection.gen.json：结构化元数据（module / 各 class 的 kind·cppName·reflectName·defaultConstruct·properties·methods，各 enum 的 values）。它供工具链与契约测试消费——例如 tests/reflection_codegen_contract_tests.cpp 会断言 JSON 里确实出现了 cppName / reflectName / 属性 cppType / 枚举 values。

接入构建（CMake）

cmake/ReflectionCodegen.cmake 提供 arp_reflection_generate()，由 CMake 自定义命令在构建期跑工具。真实用例（来自引擎根 CMakeLists.txt）：

arp_reflection_generate(
    TARGET arp_resource
    MODULE core_math
    OUT_JSON "${CMAKE_CURRENT_BINARY_DIR}/generated/reflection/arp_resource/core_math.reflection.json"
    OUT_CPP "${CMAKE_CURRENT_BINARY_DIR}/generated/reflection/arp_resource/core_math.reflection.gen.cpp"
    HEADERS "${CMAKE_CURRENT_SOURCE_DIR}/src/core/math.h"
)

它会：自动把生成的 .cpp 加入 TARGET 的源文件；建一个 <TARGET>_<MODULE>_reflection_generated 自定义目标并设为 TARGET 的依赖（改了头文件就会重新生成）；MinGW 下加 -Wa,-mbig-obj 规避大目标文件限制。

谁来调用生成的注册函数

工具只负责生成代码，不会自动注册进数据库。每个模块需要一个手写聚合函数去调用生成的入口，例如 src/resource/particle_asset_resources.cpp 的注册入口里：

arp::reflection::generated::register_core_math_reflection();
arp::reflection::generated::register_core_curve_reflection();
arp::reflection::generated::register_particle_asset_resources_reflection();

这个聚合函数再在引擎 bootstrap（或模块加载）时调用一次，就把 codegen 登记的类型填进反射数据库——于是第 06 章资源管线里的 MeshAssetResource / ParticleAssetResource 等，正是经此路径被反射登记的。

当前切片的能力边界：工具是行扫描器而非完整 C++ 编译器，明确限制有：
  • 只支持 public 的 APROP / AFUNC；非公有成员会被诊断报错。
  • AFUNC 暂不支持构造函数（返回类型为空即报错）。
  • 标记必须独占一行、且紧跟其声明（字段/方法在下一非空行）。
  • 标记体目前消费 Name="..." 与 Construct Default；其余 flag 仅记录、未参与生成。
其余能力（.inherit<B>()、指针/智能指针成员的间接值、方法默认参数等）仍需走 7.3 手写构建器——codegen 与手写可混用：先用 ACLASS/APROP 批量登记简单字段，再在同一类型上追加手写 .inherit<B>() 等。
