12 程序化生成 Contract Complete

程序化生成是 arp 里把“世界长什么样”拆成一组可复现、可约束、可分层的算法和数据的方式。它不等于“随机”，更不等于“运行时随便画点噪声”。对 WoCC 这类世界项目来说，程序化生成负责的是地形轮廓、河流走向、生物群落、资源分布、道路网络、聚落候选点和命名规则；真正的视觉资产仍然来自第 11 章讲的导入管线，以及第 06 章的资源管理。

一句话原则：程序化生成决定结构，资产管线决定外观，渲染系统决定表现。三者必须分层，不能把“噪声能跑”当作“内容完成”。

1. 程序化生成到底在做什么

在 arp 中，程序化生成通常分成四类任务：

  • 布局：地形、河道、道路、聚落、 POI 的空间关系。
  • 约束：坡度、水文、海岸线、可达性、视线遮挡、资源密度。
  • 实例化：树、石头、草、建筑、道具、效果的分布与变体选择。
  • 分层输出：近景网格、远景轮廓、LOD、mask、atlas、sidecar 数据。

也就是说，它回答的是“哪里应该有山、河、林、路、村子”，而不是“这棵树的叶子长什么样”。后者属于资源导入和材质资产的范畴。

2. 一个标准的程序化流水线

这条链路在 WoCC 里非常实用：先用 seed 和 chunk 坐标得到确定的高度场，再经过侵蚀塑形，接着根据坡度、水位和气候带划分 biome，最后把树、石头、草和道路规则撒到对应区域。对玩家来说看到的是“自然”；对引擎来说，每一步都能复现、验证、缓存和流式加载。

3. 程序化生成和资产导入的关系

程序化生成不会替代资产导入。它们更像两层分工：

层级负责什么例子
程序化生成决定位置、密度、规则、变体、层级某片森林应该偏松散还是偏密集；道路绕开陡坡还是穿过山谷
资产导入提供具体的树、石头、地表、材质和动画资源Quaternius 树族、Poly Haven 岩石、ambientCG 地表
渲染系统把结果画出来，并处理 LOD、阴影、风动、后处理植被实例、阴影贴图、雾、景深、色调映射

换句话说：程序化生成负责“森林应该出现在这里”，资产导入负责“森林里到底是哪种树”。

4. WoCC 里的实战分层

在 WoCC 这样的世界项目里，可以把程序化生成拆成下面几层：

  1. 世界底层：seed、地形高度、侵蚀、水文、海岸线。
  2. 生态层：biome、温度、湿度、树线、草线、岩石带。
  3. 实例层：树、石头、草、倒木、灌木、装饰物。
  4. 内容层：道路、聚落、洞穴、地牢、 POI。
  5. 表现层：LOD、雾、风、天空、远景、后处理。

这五层里，前两层更接近“世界规则”，中间两层更接近“内容分布”，最后一层才是“画面表现”。这样拆开后，修改任何一层都不会把整张世界重做一遍。

5. 最小可复现思路

如果你要从零写一个程序化地形生成器，最小版本通常只需要四个输入：

  • worldSeed：保证同一张世界图能复现。
  • chunkCoord：把无限世界拆成可缓存的小块。
  • heightSampler：把世界坐标转成高度。
  • scatterRules：把高度、坡度、湿度映射成实例分布。
TerrainChunk generateChunk(uint32_t worldSeed, int cx, int cz) {
  auto localSeed = hash(worldSeed, cx, cz);
  auto height = buildHeightField(localSeed, cx, cz);
  auto biome  = classifyBiome(height, localSeed);
  auto mesh   = buildChunkMesh(height);
  auto plants = scatterVegetation(biome, localSeed);
  return { mesh, plants };
}

真正的关键不是“会不会写噪声”，而是每一步都能被固定输入复现、被测试验证、被缓存保存、被流式切块。

6. 这章最重要的几条纪律

  • 程序化生成可以负责结构，但不能悄悄替代正式资产；
  • 同一组输入必须得到同一组输出，不能依赖隐式状态；
  • 能缓存的结果要缓存，能分块的结果要分块；
  • 任何会影响可见结果的规则，都要有明确参数和验证路径；
  • 如果一个系统最终会被玩家长期看到，就不要把 prototype fallback 当生产结果。

记忆版：程序化生成不是“乱画”，而是“按规则长出来”。规则负责世界，资源负责长相，渲染负责呈现。

6a. 更贴近 WoCC 的代码视角

在 WoCC 里，这个流程更接近“世界规则 + 资源选择 + 运行时实例化”的组合。下面这个例子展示了一个比较真实的分工：程序化系统只负责决定地形和生态，具体树族和地表则由资产目录提供。

struct ScatterInput {
  uint32_t worldSeed;
  int chunkX;
  int chunkZ;
  float heightMeters;
  float slope;
  float moisture;
};

struct ScatterResult {
  std::string treeFamilyId;
  std::string surfaceId;
  uint32_t instanceCount;
};

ScatterResult chooseScatter(const ScatterInput& in) {
  if (in.heightMeters > 900.0f || in.slope > 0.65f) {
    return { "quaternius_twisted_tree_family", "mossy_rock_cliff", 24 };
  }
  if (in.moisture > 0.55f) {
    return { "quaternius_common_tree_family", "leaf_root_forest_ground", 48 };
  }
  return { "quaternius_pine_family", "rocky_forest_path", 32 };
}

void buildVegetationChunk(const ScatterInput& in, TerrainChunk& chunk) {
  auto choice = chooseScatter(in);
  auto treeSet = resourceManager.findByAlias(choice.treeFamilyId);
  auto surface = resourceManager.findByAlias(choice.surfaceId);
  scatterInstances(chunk, treeSet, surface, choice.instanceCount, in.worldSeed);
}

这段代码想表达的重点不是语法，而是职责边界：chooseScatter() 是程序化规则，findByAlias() 是资源查找，scatterInstances() 才是把结果投到 chunk 里的执行层。这样做的好处是每个决定都能被测试，也能很容易切到别的资产族。
