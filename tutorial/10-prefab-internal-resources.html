10 预制体 Contract Complete

arp 引擎把第三方资产（Unity 角色/预制体文件夹）与所有内置资产统一建模为「内部资源（internal resource）」，经由 src/resource 的 ResourceManager 与内部资产包（ArpInternalAssetPackage/v1）管理。本文先讲预制体（Prefab）作为可复用资产模板的概念与资源模型，再给出当前由 prefabResourceFactory() 注册的 21 个内部资源类型的完整清单。参考项目 world_of_claudecraft 用 content/*.yaml（见 06）做数据驱动内容，其角色（boar / wolf 等）正是预制体导入器的典型输入。

Prefab ≠ SceneObject。 按引擎契约（docs/pika-prefab-sceneobject-contract.md）：预制体是资产侧的模板（描述 GameObject + Component + 子层级的形状），不是运行时场景节点；它进入场景后变为 SceneObject（见 02）。嵌套预制体编辑、Variant、apply/revert 不在本期范围内。

1. 什么是预制体

预制体是一个可复用的创作/打包模板资产，至少要能描述「对象身份 + 父子层级 + 组件负载」的形状。它的关键约定：

  • 是资产，不是节点：resource::PrefabResource 留在资产侧，绝不被当作可渲染或可更新的场景节点消费。
  • 实例 → 场景对象图：PrefabInstance -> SceneObject graph；普通场景-authored 对象与预制体实例化对象可以共存于同一场景层级（见 02）。
  • 身份保留：一个预制体实例至少保留 source prefab id，以便后续支持 override 元数据。
  • 运行时不直接消费预制体资产：场景遍历/提取只认 SceneObject 这一唯一运行时事实形状。

2. 引擎里的预制体资源模型

PrefabResource 本身是一个引用图枢纽：它不直接持有几何，而是用 UUID 引用同一资产包里的其它内部资源（模型、蒙皮网格、骨骼、动画集、材质集、运行时负载等）。这保证了预制体可被确定性地打包、重载与依赖校验。

// src/resource/prefab_asset_resources.h（节选）
struct PrefabResource : public ResourceBase {
  static constexpr const char* resourceTypeName() { return "PrefabResource"; }
  static constexpr const char* defaultEnvelopePath() { return "resources/prefab.arpres.yaml"; }

  arp::core::pmr::String name, sourcePath, sourceResourceId;
  arp::core::pmr::String modelId, skinnedMeshId, skeletonId, avatarId;
  arp::core::pmr::String animationSetId, animatorControllerId, materialSetId;
  arp::core::pmr::String runtimePayloadId, sequenceId, sequenceBindingSetId;
  arp::core::pmr::String previewStudioId;
  arp::reflection::hlist shaderPackageIds;   // 绑定 4 个着色包（basic/stylized/gui/startupSplash）
  int objectCount, componentCount, physicsColliderCount, lightHelperCount;
};

与预制体根配对的是 PrefabRuntimePayloadResource——它记录运行时 sidecar blob（确定性二进制，存于 blobs/），承载可动画的运行时状态：

struct PrefabRuntimePayloadResource : public ResourceBase {
  arp::core::pmr::String blobPath;        // 如 blobs/prefab-runtime.arpa.bin
  int blobHash, blobByteSize;
  arp::core::pmr::String defaultStateName, defaultClipName;
  int stateBindingCount, materialCount, textureCount, imageCount;
};

加载时引擎会校验 PrefabResource 依赖的 PrefabRuntimePayloadResource 是否存在，并比对 sidecar blob 的 blobHash / blobByteSize，再重建 AnimatedMeshAsset 与动画状态绑定。

3. 构建预制体（CLI + API）

从 Unity 角色/预制体文件夹转换为内部资产包（Prototype Complete）：

# Unity 角色/预制体文件夹 → 内部资产包（yaml 包目录）
arp_asset_importer --unity-prefab-folder <dir> --output-package <dir>

编程式构建走 PrefabAssetGraphBuilder::buildPackage(desc)；desc 携带 alias、displayName、sourcePath、shaderPaths 等。它会确定性地分配图内各资源 UUID（以 "ArpInternalAssetPackage.PrefabAssetGraph.v1|" 为种子），写入 manifest.arpkg.yaml + 每个资源的 .arpres.yaml envelope，并把运行时数据写成 sidecar blob。

所有边都是UUID 引用，而非路径；依赖缺失、重复 id/别名、非法 UUID 都会在包构建与图加载阶段被确定性拒绝。

4. 加载与实例化

内部资产包是一个 YAML 包目录：manifest.arpkg.yaml 记录每个资源的 id / type / alias / envelope 路径 / 依赖 / status / content hash；每个资源一个 .arpres.yaml envelope（反射序列化）。加载路径：

  1. ResourceManager 解析别名（如 prefab/unitychan-pika-visible）→ UUID；
  2. 校验 PrefabResource 依赖的 PrefabRuntimePayloadResource 存在；
  3. 比对 sidecar blob 的 blobHash / blobByteSize；
  4. 重建 AnimatedMeshAsset + 动画状态绑定（loadPrefabRuntimePayloadFromPackage()）；
  5. 运行时实例化 → SceneObject 图（见 02），预制体资产本身不被场景消费。

6. 内部资源契约与状态分级

每个内部资源类型通过 ResourceContractDescriptor{ type, contractVersion } 声明一次（如 ParticleEffectResource 为 "particle.effect/v1"），加载时用 validateResourceContract() 校验。所有资源走统一状态分级（见总览「状态分级约定」）：

Contract Complete 身份/契约已锁定并测试 Prototype Complete 原型跑通（如 prefab 导入/加载） Backend Validated 指定后端已验证 Platform Validated 多平台已验证 Production Ready 生产就绪

资产包写入与读取本身不创建任何 GPU 资源（无原生句柄、buffer、descriptor），因此它们被标记为「Backend Validated: Not applicable」——GPU 归 renderer / RHI / backend 层。

8. 快速上手清单

  1. 理解 Prefab 是资产、SceneObject 是运行时：不要直接把 PrefabResource 当作场景节点消费。
  2. 从 Unity 资产构建预制体：arp_asset_importer --unity-prefab-folder <dir> --output-package <dir>；编程式用 PrefabAssetGraphBuilder::buildPackage(desc)。
  3. 加载走 ResourceManager：别名解析为 UUID、校验 PrefabRuntimePayloadResource 依赖与 sidecar blob 哈希、重建动画资产。
  4. 实例化后接入 02 的 GameObject/Component 体系；同一资产可被多处实例复用。
  5. 需要新资产类型时，继承 ResourceBase 并在工厂注册（参考 prefabResourceFactory() 的 registerType 模式）；不要绕过 ResourceManager 用原生句柄。
  6. 所有内部资源共用同一套契约/状态/句柄模型，与项目级 ContentAssetResource（06）一致。
