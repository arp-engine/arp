02 GameObject + Component 运行时框架 Contract Complete

场景运行时（src/scene）是 arp 引擎的对象模型核心：GameObject 形成确定性的父子层级，Component 承载可复用行为，Transform 区分局部/世界变换，Scene 负责每帧的启用/启动/更新/延迟更新阶段与稳定遍历快照。本文结合 world_of_claudecraft 的组件用法逐层拆解。

对象模型总览

1. GameObject

GameObject 不可拷贝，拥有稳定的 id()、name()、parentId()、childIds()、active()，以及唯一的 TransformComponent。组件通过模板方法 addComponent<T>() 挂载（底层用 core::makeUnique，受 pmr 分配器管理）。

GameObject& root = scene.createObject("player");
MeshComponent& mesh = root.addComponent<MeshComponent>();
mesh.setResourceId("meshes/player");

root.transform().setLocalTranslation({ 0, 0, 0 });

scene.reparent(child.id(), root.id());   // 显式重父化，拒绝环
scene.setWorldTransform(root.id(), world);

层级是确定性的：稳定子节点顺序、显式重父化、循环检测、确定性非法 id 诊断。世界变换由父链 + 稳定遍历快照推导，局部变换归对象所有。

2. Component 生命周期与提取

所有组件派生自 arp::scene::Component，含启用/启动/更新/延迟更新/禁用/销毁钩子，以及一个多态的 extract() 渲染提取钩子。提取器遍历场景图、对「active 且 enabled」的组件派发 extract()，而不是对具体组件类型做 dynamic_cast。

class Component {
public:
  virtual void onEnable(const SceneUpdateContext&) {}
  virtual void onStart(const SceneUpdateContext&) {}
  virtual void onUpdate(const SceneUpdateContext&) {}
  virtual void onLateUpdate(const SceneUpdateContext&) {}
  virtual void extract(const RenderExtractContext&,
                          RenderExtractSink&) const {}  // 默认空：仅数据组件可不重写
};

SceneUpdateContext 携带 deltaSeconds 与 frameIndex；extract() 的 ctx 由提取器填充（owner、worldTransform、activeInHierarchy），组件可据此解析兄弟组件。

3. Transform：局部与世界

TransformComponent 持有 localTransform() 与 worldTransform()。局部空间归对象所有；世界空间由父链与稳定遍历快照推导。注意：引擎的 Transform 默认只含平移 + 缩放，不携带旋转/前向轴——方向类数据（如灯光方向）需由组件自行保存。

const Transform& local  = go.transform().localTransform();
const Transform& world  = go.transform().worldTransform();
go.transform().setLocalTranslation({ x, y, z });

4. Scene：每帧更新与提取

Scene 本身继承自 GameObject，是根节点。其 update() 按确定顺序跑四个阶段：enable/disable → start → update → lateUpdate。extractTraversalSnapshot() 产出稳定的遍历快照，供相机解析、2D/3D/UI 队列提取使用。

Scene scene("world");
GameObject& player = scene.createObject("player");

SceneUpdateResult r = scene.update({ .deltaSeconds = dt, .frameIndex = frame });
SceneTraversalSnapshot snap = scene.extractTraversalSnapshot({ /* options */ });
阶段做什么备注
enable/disable根据 active 状态切换组件启停确定性
start首次启用后跑一次 onStart幂等
update主更新 onUpdate输入/角色/动画驱动
lateUpdate延迟更新 onLateUpdate相机跟随在此跑

5. 相机与输入（确定性顺序）

相机是普通 GameObject + TransformComponent + 共享 CameraComponent；CameraResolver 消费遍历快照产出 ResolvedCamera。测试过的控制顺序是：

平台原始事件 → InputSystem 动作快照 → (可选) UI 输入路由
→ PlayerInputComponent → CharacterControllerComponent(update)
→ CameraFollowComponent(late update) → 遍历快照 → CameraResolver
→ 2D / 3D / UI RenderQueue 提取
  • PlayerInputComponent：只暴露高层 InputActionState，不移动对象、不改相机、不暴露原生键码。
  • CharacterControllerComponent：仅消费来自 PlayerInput 的意图，更新自身 Transform 与移动状态。
  • CameraFollowComponent：消费目标 Transform + 高层 look/zoom 动作，在 lateUpdate 确定性更新相机 Transform。

参考实例：world_of_claudecraft 的组件

该项目在引擎 Component 之上定义了一批「自带类型」的组件，均重写 extract() 推送确定 typeId 的 payload（sink 必须拒绝未知 typeId，不猜测、不静默回退）：

// 类型安全地查找兄弟组件（引擎用扁平 vector 存组件，无内置 finder）
const MeshComponent* m =
  findComponentByType<MeshComponent>(gameObject);

WoCC 的 MeshComponent 使用「resourceId 字符串 + baseColor」的运行时模型（绘制时经 ResourceManager 解析），与引擎 3D 模块的 MeshHandle/MaterialHandle 模型不同。这是项目级的契约选择，文档与 sink 必须据此校验。

内存与热路径约束

运行时动态容器统一使用 core::pmr（core::makeUnique/makeShared）。新生产代码不得用默认 STL 动态容器、默认 STL 分配助手或裸 new/delete。提取不拷贝静态顶点数据到热路径；2D/3D/UI 保持独立逻辑队列，默认在一 pass 内按 3D→2D→UI 提交。

快速上手清单

  1. 用 scene.createObject(name) 建对象，用 addComponent<T>() 挂组件。
  2. 变换放 TransformComponent；方向/特殊数据由组件自身保存。
  3. 渲染相关组件重写 extract()，推送自描述的 payload（带确定 typeId）。
  4. 每帧 scene.update(...) → extractTraversalSnapshot(...) → 交给渲染器/相机解析。
  5. 保持后端中立与 pmr 分配，不要在任何热路径做文件/网络 IO 或原生句柄操作。
