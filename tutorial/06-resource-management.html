06 资源管理 Contract Complete

arp 引擎的运行时资源由 src/resource 统一管理：资源有显式身份（UUID + 别名）、确定性的生命周期状态、依赖元数据与内容指纹；加载走「类型化 ResourceBase → ResourceManager 准入/加载 → ResourceHandle<T> 类型化句柄查询」的单一所有权模型。本文讲清楚这条资源生命周期，并用 world_of_claudecraft 的 ContentAssetResource 演示如何把数据驱动的 YAML 内容接入同一套资源管理器。

引擎不按资源种类各自搞一套运行时管理器：网格、纹理、UI 文档、着色器包、Prefab，乃至游戏内容 YAML，全部共用同一个 ResourceManager，靠「类型化 ResourceBase 子类 + 契约版本」区分。这避免了隐藏的原生句柄与静默兼容回退。

资源生命周期与状态机

每个资源从声明到卸载都经过确定的状态。ResourceState 枚举定义了这些状态：

状态含义：Declared（已声明 identity）、Loading（正在加载）、Ready（可被句柄查询）、Failed（确定性失败诊断）、Stale（句柄指向的 generation 已过期）、Unloaded（已卸载）。重新加载时只有内容哈希真正变化才会推进 generation 并进入新 Ready，否则保持原状或转 Failed——绝不发布「半成品 Ready」。

ResourceBase：自定义资源的基类

新资源类型只需继承 arp::resource::ResourceBase，并在构造时填入 ResourceReference（id / type / alias / status / displayName），按需重写几个钩子：

class ARP_API ResourceBase {
public:
  virtual ResourceLoadResult load(ResourceManager&, const ResourceLoadContext&);
  virtual bool collectFileReadIntents(ResourceManager&,
        core::pmr::Vector<ResourceFileReadIntent>&, core::pmr::String& diagnostics) const;
  virtual ResourceGraphStage processingStage() const noexcept;
  virtual std::size_t processedByteCount() const noexcept;
  virtual void appendContentFingerprint(core::StableHash64&) const noexcept;
  void addDependency(ResourceDependency);   // 显式声明依赖
};
  • load()：实际解析（读文件 / 程序化生成 / 解析 YAML），由 ResourceManager::loadResource() 在准入前调用。
  • collectFileReadIntents()：声明本资源需要从磁盘读取哪些文件（角色、字节上限），供分阶段图执行器在 FileRead 阶段批量读取。
  • processingStage()：返回该资源在图执行中的阶段，如 ResourceGraphStage::TypedProcessing。
  • appendContentFingerprint()：把决定内容唯一性的字段喂给稳定哈希（见下方「内容指纹与重载」）。
  • addDependency()：声明对其它资源的依赖（重复自动去重），依赖 id 与别名都是 UUID，而非路径。

ResourceManager：声明 / 加载 / 查询

ResourceManager 是资源的唯一注册与缓存中心。常见入口：

// 1) 声明 identity（要求 UUID 格式 resourceId）
manager.declareResource(resourceId, "ContentAssetResource");

// 2) 类型化同步加载：自动 makeUnique<T> 并走共享生命周期
ResourceLoadResult r = manager.load<MeshAssetResource>(
    ResourceLoadContext{}, resourceId, sourcePath);

// 3) 类型化异步加载（提交一个有限 work item 到 WorkService）
manager.loadAsync<MeshAssetResource>(workService, completion, ctx, resourceId, sourcePath);

// 4) 图加载：显式节点 + 依赖，拓扑排序后逐节点加载
ResourceGraphRequest req;
req.rootResourceId = rootId;
req.nodes.push_back({ core::makeUnique<PrefabResource>(...), { deps... } });
manager.loadGraph(std::move(req));

// 5) 查询：按 id 或别名拿类型化句柄
auto h = manager.find<MeshAssetResource>(resourceId);
auto a = manager.findByAlias<ContentAssetResource>("wolf");
API作用
declareResource(id, type)登记资源 identity；id 必须是 UUID 格式。
load<T>(ctx, args...)类型化同步加载，返回 ResourceLoadResult。
loadAsync<T>(ws, cb, ctx, args...)异步加载，提交一个有限 work item。
loadGraph(req) / loadGraphAsync(...)确定性图加载，校验重复 id/别名、缺失依赖节点、依赖环、非法 UUID、非法 legacy 状态。
find<T>(id) / findByAlias<T>(alias)返回 ResourceHandle<T>；未就绪或类型不符时句柄不为 ready。
stateOf / diagnosticsOf / resolveAlias / recordSnapshot查询状态、诊断、别名解析、只读记录快照。
unload(id) / retireResource / releaseRetiredResources卸载、退役（保留旧 generation 用于回滚）、释放退役资源。

ResourceHandle<T>：类型化、带代的查询

句柄是查询资源的标准方式，它携带 generation，能区分「资源已失效」与「尚未就绪」：

auto h = manager.find<MeshAssetResource>(resourceId);
if (h.ready()) {                      // Ready 且 generation 匹配
  const auto* mesh = h.get();         // 返回 const T*
  // ... 使用 mesh->mesh() ...
} else if (h.stale()) {                 // 指向的 generation 已过期（被重载）
  // 重新 find 以获取新 generation
}
// h.id() / h.state() / h.diagnostics() 可读元数据与失败原因

组件只持有 resourceId 字符串，不持有裸指针；每帧通过 find<T>(id) 拿句柄。这样重载（热更新）发生时，旧句柄变 stale，组件重新查询即可拿到新资源——单一所有权、无悬挂指针。

分阶段图执行：ResourceGraphExecutor

异步图加载由 ResourceGraphExecutor 拥有。它校验并拓扑排序显式节点，按 ResourceGraphStage 分阶段推进：

enum class ResourceGraphStage : std::uint8_t {
  Validation,     // 校验 id/别名/依赖/状态
  FileRead,       // FileService 读取声明文件
  YamlParse,      // 解析 YAML
  ImageDecode,    // 解码图像（纹理）
  TypedProcessing,// 类型化资源处理
  Admission,      // 准入到 ResourceManager
  Completion      // 经 CompletionQueue 发布结果
};

节点数、文件读取数、源字节、解码字节、完成派发次数都有显式预算；取消、队列拒绝、服务关闭、依赖失败、读取/解码字节、阶段顺序、耗时与恰好一次完成，都是可观测遥测。ResourceLoadContext::requirePreloadedSources 可阻止文件型资源在该路径上回退到阻塞文件辅助函数。

内容指纹与重载（Reload）

每个资源通过 appendContentFingerprint() 把决定内容唯一性的字段喂入 StableHash64。重载时 reloadResource() 先快照旧记录，尝试新加载：

  • 加载失败或内容哈希未变 → 回滚到旧快照，generation 不变。
  • 内容哈希变化且加载成功 → 推进 generation，资源进入新 Ready。

ResourceReloadTelemetry 报告 generation、oldContentHash、newContentHash、committed、rolledBack、retiredCount 与失效依赖。绝不发布「部分就绪」的 generation。

ResourceReloadResult rr = manager.reloadResource(core::makeUnique<MeshAssetResource>(id, path));
if (rr.committed) { /* 新 generation 已生效 */ }
else if (rr.rolledBack) { /* 保持旧状态 */ }
// rr.telemetry.invalidatedDependents —— 哪些依赖被失效

预算与遥测

ResourceBudgetConfig 给出各维度的显式上限（值为 0 表示该维度不限制）：

字段含义
maxGraphNodes图节点数上限
maxDecodedBytes解码字节上限（会下推到加载上下文）
maxUploadBytes上传字节上限（由拥有该资源的 renderer/UI 契约强制）
maxGlyphPages字形页上限
maxReloadGenerations重载 generation 上限
maxRetainedRecoveryBytes退役资源保留恢复字节上限
maxCompletionDispatchCount完成派发次数上限
maxDiagnosticsLength诊断字符串长度上限

预算耗尽会产生确定性的 ResourceLoadResult/ResourceReloadResult 诊断并累加计数；绝不出现无界分配或静默部分结果。telemetry() 返回当前预算配置与累计耗尽次数的稳定快照，便于诊断与回归检查。

ResourceBudgetConfig cfg;
cfg.maxGraphNodes = 2048;
cfg.maxDecodedBytes = 256u * 1024u * 1024u;
manager.setBudgetConfig(cfg);
const auto t = manager.telemetry();

契约与状态标签

资源类型通过 ResourceContractDescriptor{ type, contractVersion } 声明一次；加载时用 validateResourceContract() 校验。状态文本走统一的 ResourceStatus 契约（ContractComplete → ProductionReady 等），未知标签、不允许的标签、非法「状态晋升」都会产生确定性诊断——生产加载器不得维护私有的自由格式状态解析。

inline constexpr ResourceContractDescriptor kContentAssetContract {
  "ContentAssetResource", "content.asset/v1" };

参考实例：world_of_claudecraft 的内容资源

该项目把 content/*.yaml（生物 / 区域 / 物品）作为数据驱动内容接入同一个 ResourceManager，而不是再写一套内容管理器。要点：

  • ContentAssetResource 继承 ResourceBase，契约 "content.asset/v1"；构造时填入 ResourceReference。
  • 资源管理器要求 id 为 UUID；内容文件用的是人类可读逻辑 id（如 "wolf"、"eastbrook_vale"），于是从逻辑 id 确定性地合成一个格式合法的 UUID，并把逻辑 id 注册为别名。这样 findByAlias<ContentAssetResource>("wolf") 就能按名查到资源。
  • load() 解析 YAML 并填充 CreatureDesc / ZoneDesc / ItemDesc 描述符（定义在 content/content_manager.h）。
  • 场景像查询网格一样查询内容：manager.find<ContentAssetResource>(id) 与 findByAlias 走同一套路径。
// content/content_asset_resource.h（节选）
class ContentAssetResource final : public arp::resource::ResourceBase {
public:
  ResourceLoadResult load(ResourceManager&, const ResourceLoadContext&) override;
  ResourceGraphStage processingStage() const noexcept override
    { return ResourceGraphStage::TypedProcessing; }
  void appendContentFingerprint(core::StableHash64&) const noexcept override;
  const CreatureDesc& creature() const noexcept;
};

// 场景侧查询（与网格同路）：
auto wolf = manager.findByAlias<ContentAssetResource>("wolf");
if (wolf.ready()) spawn(wolf->creature());

引擎内置的 MeshAssetResource（"mesh.asset/v1"）是另一个对照：它支持 GLB 文件加载与程序化网格（grid / cube / 自定义），所有网格数据所有权转交给 ResourceManager，组件只按 resourceId 引用。这与内容资源是同一所有权模型的两种实例。

快速上手清单

  1. 新资源继承 ResourceBase，用 ResourceReference 填入 id/type/alias/status；id 用 UUID（人类可读名注册为别名）。
  2. 重写 load() 解析数据、collectFileReadIntents() 声明文件读取、appendContentFingerprint() 喂内容指纹、processingStage() 返回阶段。
  3. 用 manager.load<T>(ctx, args...) 同步加载，或用 loadAsync<T>() 异步提交到 WorkService；多资源依赖用 loadGraph()。
  4. 组件只持有 resourceId，每帧 find<T>(id) 拿 ResourceHandle<T>；用 ready()/stale() 判断就绪与过期。
  5. 热更新调用 reloadResource()，依赖指纹哈希决定是否推进 generation；用 telemetry() 与 ResourceBudgetConfig 控制预算。
  6. 不要引入第二个运行时资源管理器；所有资源（网格 / 纹理 / UI / 内容）共用一个 ResourceManager。
