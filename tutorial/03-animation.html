03 动画 Contract Complete Prototype Complete

arp 引擎的动画系统（src/animation）覆盖：关节变换与剪辑采样、动画状态机（混合/过渡）、AnimatorController（参数驱动的状态机）、骨骼与逆绑定矩阵、CPU 蒙皮。当前骨骼姿态数学、动画 GLB 导入、CPU 蒙皮均已 Contract Complete，但原生后端验证尚在进行。

动画数据模型

底层数据类型直接对应 glTF 动画语义：每个关节一条 AnimationChannel，含若干 JointKeyframe（time + transform），以及对 translation/rotation/scale 的 targetPath。

struct JointTransform { Vec3 translation; Quat rotation; Vec3 scale; };

struct AnimationChannel {
  uint32_t jointIndex;
  std::pmr::vector<JointKeyframe> keyframes;
  std::pmr::string targetPath = "translation";
  std::pmr::string jointName;
};

struct AnimationClip {
  std::pmr::string name;
  float durationSeconds;
  std::pmr::vector<AnimationChannel> channels;
  std::pmr::vector<AnimationEvent> events;  // 时间线事件
};

// 在 timeSeconds 采样整条 clip，输出每关节的 pose
bool sampleClip(const AnimationClip&, float timeSeconds,
                std::pmr::vector<JointTransform>& outPose);

// 收集 [prev, cur] 区间内触发的事件（考虑 looping）
void collectEvents(const AnimationClip&, float prev, float cur,
                   bool looping, std::pmr::vector<AnimationEvent>&);

轻量状态机：AnimationStateMachine

对于简单混合需求，animation::AnimationStateMachine 提供 play()、transitionTo()（带过渡时长）、advance()，并暴露当前状态名、当前时间与混合权重。

AnimationStateMachine sm;
sm.play(idleClip);
sm.transitionTo(runClip, 0.2f);   // 0.2s 过渡
sm.advance(dt);
float w = sm.blendWeight();      // 过渡期混合权重

AnimatorController：参数驱动状态机

更完整的状态机由 AnimatorControllerAsset（数据） + AnimatorControllerRuntime（运行时）构成，支持 Bool/Float/Int/Trigger 参数、条件迁移、退出时间（exit time）与过渡时长。

struct AnimatorControllerAsset {
  std::pmr::string name;
  std::pmr::string defaultStateName;
  std::pmr::vector<AnimatorParameterDefinition> parameters;
  std::pmr::vector<AnimatorState> states;
  std::pmr::vector<AnimatorTransition> transitions;
};

AnimatorControllerRuntime ctrl(asset);
ctrl.setFloat("speed", 3.5f);
ctrl.setBool("grounded", false);
ctrl.fireTrigger("attack");
ctrl.advance(dt);
const std::pmr::string& clip = ctrl.activeClipName();

骨骼与蒙皮

animation 提供 Skeleton（关节 + 逆绑定矩阵）、buildModelPose()（局部 pose → 模型空间矩阵）与 buildSkinMatrices()（乘逆绑定得到蒙皮矩阵）。矩阵工具含 Mat4 乘法、仿射求逆、点/向量变换。

struct Joint { std::pmr::string name; int parentIndex; Mat4 inverseBindMatrix; };

// 局部 pose → 模型空间 pose
std::pmr::vector<Mat4> modelPose =
  buildModelPose(skeleton, localPose);
// 模型空间 pose → 蒙皮矩阵（skin = modelPose * inverseBind）
std::pmr::vector<Mat4> skin =
  buildSkinMatrices(skeleton, modelPose);

当前 Project Lane 路径在 CPU 上烘焙蒙皮顶点（cpu_skinning），并把结果作为普通网格经渲染器/RHI 路径上传。GPU 蒙皮尚未就绪，Project Lane 暂时以 CPU 蒙皮作为回退路径。

参考实例：world_of_claudecraft 的动画

该项目尚未接入骨骼蒙皮，而是用一个轻量 MovementAnimator（非状态机）直接根据 MovementState 计算视觉修饰（bob 偏移、缩放、lean 角度），再由 AnimationComponent 把这些修饰写回 GameObject 的 TransformComponent。其 AnimationClipId 枚举（Idle/Walk/Run/Jump/Fall）预留了未来对接引擎 AnimationStateMachine 的接口。

// gameplay/animator.h
AnimatorVisuals v = animator.update(movement, dt, totalTime);
// → 写回 TransformComponent：baseTranslation + bob，scale，lean

// app/components.h — AnimationComponent::updateFromMovement()
void updateFromMovement(const MovementState&, float dt, GameObject& owner);

这是「引擎接口 → 项目用法」的典型对照：引擎提供通用 AnimationStateMachine/AnimatorControllerRuntime 与 sampleClip；项目先用轻量驱动跑通视觉，待骨骼资源到位后再切到 buildSkinMatrices + 状态机。

快速上手清单

  1. 用 AnimationClip + sampleClip() 采样关节 pose；需要时间线事件用 collectEvents()。
  2. 简单混合用 AnimationStateMachine；复杂参数驱动用 AnimatorControllerAsset + AnimatorControllerRuntime。
  3. 骨骼模型：buildModelPose → buildSkinMatrices，把蒙皮矩阵送渲染器（当前建议 CPU 烘焙回退）。
  4. 在角色的 Component::onUpdate 里驱动动画并写回 TransformComponent。
