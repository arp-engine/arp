04 粒子 Prototype Complete

arp 引擎的粒子/特效系统（src/renderer/particles）是一个确定性、后端中立的 CPU 模拟器：ParticleSystem 管理发射器生命周期与粒子池，按「视觉家族（VisualFamily）」决定渲染方式，并通过 collectActiveParticles() 把粒子交给渲染器的 DrawPlan 与 RHI 录制。本文结合资产导入与运行时 API 讲解。

系统链路

1. ParticleSystem 与品质档

系统以 ParticleSystemDesc 构造，约定最大粒子数与最大发射器数。particleSystemDescForProfile() 把品质档映射为预算：

ParticleQualityProfilemaxParticlesmaxEmitters
Low76816
Medium204832
High500048
Desktop1200096
 
ParticleSystem ps(particleSystemDescForProfile(ParticleQualityProfile::Desktop));
ParticleFrameInput input;
input.deltaSeconds = dt;
input.hostVelocity = playerVelocity;   // 粒子随宿主位移/继承速度
ps.update(input);                  // 推进一帧模拟
const auto& parts = ps.particles();   // 给渲染器读取

2. 发射器（Emitter）

用 addEmitter() 注册一个 ParticleEmitterDesc；返回 ParticleEmitterHandle（含 index + generation，generation mismatch 会被拒绝）。生命周期 API：enableEmitter / disableEmitter / triggerBurst()（一次性爆发）。

ParticleEmitterDesc d;
d.name = "muzzle";
d.maxParticles = 256;
d.spawnRatePerSecond = 120.0f;
d.particleLifetimeSeconds = 0.6f;
d.shape = ParticleEmitterDesc::EmitterShape::DirectionalForward;
d.velocityMin = { 0, 1, 0 };   // 前向轴（枪口火焰）
d.startColor = { 1, 0.8, 0.3, 1 };
d.endColor   = { 1, 0.8, 0.3, 0 };

ParticleEmitterResult r = ps.addEmitter(d);
if (r.valid()) ps.triggerBurst(r.handle, 32);
else log(r.diagnostics);   // 预算超限/非法契约 → 确定性诊断

发射器支持丰富的契约：发射形状（Point/Cone/Sphere/Box/DirectionalForward/RadialBurst）、旋转与轨道（orbit）、噪声/外力场、继承速度、软粒子深度淡出、Trail/Beam、Flipbook 子 UV、碰撞与子发射器（collision → sub-emitter）。

3. 视觉家族（VisualFamily）

渲染方式由 ParticleMaterialBinding 的 shaderFamilyId（或回退 blendMode）确定性地映射为 ParticleVisualFamily——绝不靠颜色启发式猜测。家族决定 L2 绘制语义与 billboard 模式。

enum class ParticleVisualFamily : uint32_t {
  Unknown, SpriteAlpha, SpriteAdditive, LightningThin,
  StormCloud, FallbackLegacy, Trail, Beam, MeshParticle, Count
};

// shaderFamilyId 决定家族；缺失时回退到 blendMode
ParticleVisualFamily f = visualFamilyFromBinding(binding);
// billboard 模式：0=ViewAligned 1=LocalAligned 2=WorldAligned
uint32_t bm = billboardModeFromString(binding.billboardMode);
shaderFamilyId视觉家族典型用途
ParticleSpriteAlphaSpriteAlpha烟雾、尘埃
ParticleSpriteAdditiveSpriteAdditive火焰、光晕
ParticleLightningThinLightningThin电流（渡劫雷云）
ParticleStormCloudStormCloud雷云
ParticleTrail / BeamTrail / Beam拖尾、激光
ParticleMeshParticleMeshParticle实例化 3D 网格粒子

4. 确定性模拟与遥测

模拟使用 LC 线性同余随机数（nextRandom），相同种子产生相同粒子数——这对回放、测试与跨平台一致性至关重要。update() 后读取 telemetry() 可得存活/生成/淘汰/丢弃/碰撞/子发射等计数。

auto t = ps.telemetry();
// t.aliveParticles / t.spawnedThisFrame / t.droppedSpawns
// t.collisionEvents / t.subEmitterSpawns / t.budgetDenials

热路径约束：运行时容器用 core::pmr；无默认 STL 动态容器、无每帧着色器编译、无每帧管线创建（管线仅建一次）、无文件/网络 IO、无裸 new/delete；上传/暂存资源由后端拥有（backendOwnedStaging）。

5. 渲染：DrawPlan 与 RHI

集成管线里，collectActiveParticles() 取出粒子数据 → buildParticleDrawPlan 生成 6 顶点/四边形的绘制计划（当前 RHI 仅 drawIndexed，非索引 draw() 仍在契约缺口中）→ recordParticleDrawPlan 经 RHI 编码器录制。绘制按 back-to-front 确定性排序。

// 参考命令（Pika 产品可执行文件）
arp_pika.exe --mode particle-vfx-demo \
  --particle-fixture tests\fixtures\unity_particle\fixture_one_shot.yaml \
  --frames 2

参考实例与导入流水线

粒子资产可从 Unity ParticleSystem YAML fixture 经独立 importer 转换：

arp_asset_importer --unity-particle-prefab <file> --output-package <dir>

导入 → 转换 → ParticleEffectResource → 写内部资产包 → ResourceManager 加载（按 UUID/alias 查找）→ 运行时 ParticleVfxRuntimeSession 绑定并触发。资产包支持哈希校验、生成号增量、无效数据回滚。

已知限制：① RHI 缺非索引 draw()，原生后端可见渲染需新增该入口；② Vulkan/Metal/WebGPU 后端未验证；③ 原生可视化像素验证与美术评审仍是外部门槛；④ 当前 importer 不支持 Unity 嵌套 gradient.m_Gradient.alphaKeys 的 alpha-over-lifetime 路径。

快速上手清单

  1. 按品质档构造 ParticleSystem（Desktop 用于桌面，移动端用 Low/Medium）。
  2. 用 addEmitter(ParticleEmitterDesc) 添加发射器，检查 ParticleEmitterResult 的 diagnostics。
  3. 每帧 update(ParticleFrameInput)；需要爆发调用 triggerBurst()。
  4. 通过 ParticleMaterialBinding.shaderFamilyId 明确视觉家族，不要靠颜色推断。
  5. 从 particles() 取数据交给渲染器，并监控 telemetry() 的预算/碰撞计数。
