Anime Render Pipeline · Commercial Engine Blueprint

引擎技术演进蓝图

这份蓝图把当前渲染管线项目推进为商业引擎形态：用户侧锚定 Unity 的概念和内容格式， 实现侧吸收 Unity、Unreal、Godot、O3DE、现代 FrameGraph 和移动端渲染器的长处， 同时守住现有 RHI、FrameGraph、Slang、跨平台边界和热路径约束。

状态：Contract Complete for planning 日期：2026-05-13 锚点：Unity-facing content 运行时：C++17 + RHI + FrameGraph

当前基础

渲染核心

已有 Null/Vulkan/Metal RHI 形态、FrameGraph 编译计划、Renderer draw plan、GI 计算计划、Slang 反射和隐藏窗口 smoke。

内容与工具

已有 glTF/GLB/FBX/Unity 角色导入合同、材质/UI JSON schema、asset importer CLI、材质编辑器和角色查看器。

主要缺口

缺少商业引擎用户层：AssetDatabase、Scene、GameObject、Prefab、ProjectSettings、Addressables、Editor Shell 和统一组件生命周期。

硬约束

渲染业务必须通过 RHI device、RHI command encoder、FrameGraph、renderer draw plan 或 RenderPipelineFeature 表达；src/renderer、src/gui、src/render_graph 不能引入 Vulkan、Metal、Android、iOS 原生图形头。

Slang-only shader Null → Vulkan → Metal 语义同步 禁止 native handle 泄漏 禁止热路径 IO/网络/无界分配 Windows 统一 MinGW 验证

Unity 内容格式锚点

用户概念 建议格式 说明
ProjectAssets/、ProjectSettings/*.asset、Packages/manifest.json尽量贴近 Unity 项目结构。
Asset identity.meta + GUIDGUID 是稳定身份，路径只是当前位置。
Scene.unity 风格 YAML + 编译后 package文本格式用于创作，二进制/缓存格式用于运行时。
Prefab.prefab 风格 YAML后续必须支持嵌套 Prefab、Variant 和 override。
GameObject名称、active、Transform、Component 列表用户心智保持 Unity；内部可压平成更紧凑的运行时数据。
Componenttype、enabled、serialized fieldsC++ Component 优先，脚本桥后置。
Material.mat 风格 YAML/JSONShader 引用和属性由 Slang reflection 校验。
ShaderSlang 源码 + Unity-like metadata不把 HLSL/ShaderLab 作为源语言。
Animator.controller、Avatar、clips、masks现有 Unity character importer 成为官方路径。
Addressablescatalog、groups、labels运行时用确定性 catalog 和依赖包加载。
QualitySettingsProjectSettings/QualitySettings.asset驱动渲染管线、移动预算、阴影、GI、后处理和纹理压缩。

架构分层

1. Authoring Layer

项目、资产数据库、导入设置、Inspector、Scene/Prefab 文件和 BuildProfile。允许文件 IO 和离线导入依赖。

2. Runtime Content Layer

编译包、GUID 映射、场景实例、Prefab 实例化计划、材质表、动画图、UI layout 和 Addressables catalog。

3. Gameplay Layer

GameObject/Component API、场景生命周期、Transform 层级、Update 阶段、输入、动画、音频、物理和存档。

4. Renderer Layer

RenderPipelineAsset、RendererFeature、draw plan、材质/灯光/世界抽取、剔除、批处理、GI、阴影、后处理和 GUI。

5. FrameGraph Layer

Pass/Resource 编译计划、transition、transient alias、load/store、移动 tile hints、queue role 和 imported backbuffer 保护。

6. RHI/Backend/Platform

资源、descriptor、pipeline、command list、capability、同步、deferred destruction、Vulkan/Metal/Null 和平台生命周期。

系统蓝图

1. Project / AssetDatabase / GUID

建立 Unity-like .meta、GUID、ImporterRegistry、DependencyGraph 和确定性缓存键。运行时不再依赖路径识别资产。

验收焦点

  • 重命名资产后 GUID 保持稳定。
  • 重复 GUID 可诊断。
  • 隐藏样例按 GUID 加载 package。

2. Scene / GameObject / Component / Prefab

增加 src/scene，提供 Scene、GameObject、Transform、ComponentRegistry、PrefabInstance 和序列化。

验收焦点

  • Prefab Variant override 优先级正确。
  • Scene 可构建 renderer::RuntimeScene。
  • 隐藏窗口渲染 package scene 两帧。

3. Runtime Package / Addressables / Streaming

扩展 package manifest，加入 ContentCatalog、AssetBundleManifest、RuntimePackageReader 和 AsyncLoadQueue。

验收焦点

  • Address → GUID → 依赖闭包确定。
  • 源资产目录缺失时 package-only 启动成功。
  • 移动端内存压力可驱逐缓存。

4. RenderPipeline / RendererFeature

把当前渲染配置提升为序列化的 RenderPipelineAsset，RendererFeature 管理阴影、GI、角色 NPR、Outline、粒子、后处理、GUI 和 debug view。

验收焦点

  • 不同 QualityProfile 产生不同 FrameGraph pass。
  • Vulkan hidden smoke 覆盖 scene、GUI、GI、shadow、postprocess。
  • 移动端验证 frame shape parity。

5. RHI / Synchronization / Backend Capabilities

继续强化 capability、resource view、upload、descriptor、frames-in-flight、deferred destruction 和 shutdown drain。

验收焦点

  • 不支持的能力给出 portable rejection reason。
  • 正常帧不做 device idle 等待。
  • Null、Vulkan、Metal 语义同步。

6. Shader / Material / Visual Authoring

Material 使用 Unity-like .mat，Shader 继续 Slang-only；metadata 暴露 Properties、Pass、Inspector 分类和 variant。

验收焦点

  • 缺失必需纹理在 draw 前失败。
  • SPIR-V、MSL、reflection 同步生成。
  • descriptor/pipeline 来自 reflection。

7. Animation / Avatar / Character

把 Unity controller、Avatar、clip、mask、retargeting 作为角色导入主线；CPU skinning 做正确性基线，GPU skinning 后续推进。

验收焦点

  • AnimatorController transition 和 blend tree 单测。
  • 角色预览隐藏运行 60 帧。
  • 移动端动画内存和更新时间预算明确。

8. GUI / UI Document / Editor UI

用当前 retained GUI 承载 runtime UI 和 editor UI，格式参考 Unity UI Toolkit，但执行路径保持自研 GUI。

验收焦点

  • 生产文本路径、Unicode、fallback font。
  • touch、安全区、DPI、虚拟键盘。
  • 500 节点 GUI 有 batching 和 timing。

9. Physics / Collision / Navigation

用户侧提供 Rigidbody、Collider、CharacterController、Trigger、NavMesh；实现先做合同和组件数据，再选择 Jolt/Bullet/PhysX 或轻量自研。

验收焦点

  • Raycast、Overlap、Trigger 顺序测试。
  • 固定步长 scheduler。
  • Debug draw 通过 renderer draw plan。

10. Audio

提供 AudioSource、AudioListener、AudioMixer、Clip 和空间化基础；导入阶段解码/转码，运行时读取 package。

验收焦点

  • play/pause/stop 和 mixer volume 单测。
  • Android/iOS audio focus、pause/resume。
  • Streaming、spatialization 和内存预算。

11. Scripting / Gameplay Framework

短期采用 C++ Component 和 Unity-like 生命周期；脚本桥等 ComponentRegistry 与序列化稳定后再选型。

生命周期

  • Awake、OnEnable、Start
  • FixedUpdate、Update、LateUpdate
  • OnDisable、OnDestroy

12. Editor / Tools

把材质编辑器和角色查看器扩展为 EditorApplication、AssetBrowser、Hierarchy、Inspector、SceneView、GameView、BuildProfileWindow。

验收焦点

  • Command undo/redo 和 dirty-state。
  • 编辑 material、prefab、scene transform 并保存。
  • Editor viewport 走同一 renderer pipeline。

13. World / Streaming / Open World

以 additive scene、Addressables、world cell、LODGroup、bounds 和内存预算策略承载开放世界。

验收焦点

  • camera movement 下 cell 和 LOD 选择正确。
  • 512m stylized world slice 从 package streaming。
  • 移动端内存压力可卸载 cell。

14. Particles / VFX / Timeline

ParticleSystem 先 CPU 正确性，GPU 粒子在 compute/storage buffer 合同成熟后推进；Timeline 管动画、音频、相机、VFX 和事件。

验收焦点

  • 发射数量、曲线采样、seed 确定性。
  • 隐藏 VFX sample 无热路径分配尖峰。
  • 质量档控制移动端 VFX 成本。

15. Input / Platform Services / Lifecycle

提供 InputActionMap、binding、touch、pointer、keyboard、gamepad 和 UI navigation；平台层统一 pause/resume/surface loss/memory warning。

验收焦点

  • Action phase transition 单测。
  • 样例不再直接依赖 SDL 输入细节。
  • Android/iOS 生命周期真实设备验证。

16. Performance / Telemetry / Diagnostics

扩展 CPU/GPU timing、memory budget、draw/material/texture counter、asset load diagnostics、debug label 和 profiler UI。

验收焦点

  • 预算超限产生 warning。
  • 隐藏样例输出 pass timing 和 memory summary。
  • 移动端 thermal/memory 报告。

17. Build / CI / Distribution / Public API

明确 public/internal header，补 CMake install/export、平台 preset、feature manifest、sample integration docs 和 package validation。

验收焦点

  • PackageManifest 排除 backend/internal header。
  • out-of-tree sample 可链接 installed engine。
  • Android/macOS/iOS 预设可给出清晰 SDK 诊断。

不可省略的验证门禁

每阶段必须保留

  • 一个快速单元或合同测试。
  • 一个 smoke 或 hidden-window 验证路径。
  • Shader 可见行为变化时重新生成 SPIR-V、MSL 和 reflection。
  • 新增 RHI 能力先补 capability/contract test。

跨平台同步

  • 新增 format、resource state、descriptor、pipeline state 同步 Null/Vulkan/Metal 语义。
  • 架构边界测试覆盖 native header 泄漏。
  • 移动端改动说明 Android/iOS 生命周期、surface/layer、swapchain、暂停恢复和内存预算。
  • Windows 本地统一走 MinGW 验证。
