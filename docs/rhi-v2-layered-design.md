## Positioning

L2 is the engine-facing GPU API. It is WebGPU-like in object safety and lifetime rules, Vulkan-grade in explicit rendering capability, and Descriptor-based for resource binding.

L2 is not a WebGPU compatibility layer and must not be constrained to the WebGPU feature set. WebGPU is one backend target with an internal translation layer; it does not define the upper bound of the engine API.

## Status Taxonomy

- Contract Complete: The public or semantic contract is specified and covered by deterministic tests, but runtime/backend implementation or hardware validation may still be pending.
- Prototype Complete: A working implementation exists behind explicit gates or limited scope, with fast smoke coverage, but it is not yet the production default.
- Backend Validated: Backend-native lowering or runtime behavior has passed the relevant backend smoke/contract matrix on the named platform.
- Platform Validated: Browser, mobile, desktop, or lifecycle behavior has passed platform-level smoke or lifecycle validation on the named deployment target.
- Production Ready: The feature is the intended production path, old fallback paths are retired or explicitly quarantined, and the full regression/smoke matrix has current evidence.

Status distinction guardrails:

- Contract Complete is not Backend Validated.
- Prototype Complete is not Backend Validated.
- Backend Validated is not Platform Validated.
- Platform Validated is not Production Ready.
- Production Ready requires backend, platform, migration, telemetry, lifetime, and final smoke evidence.

## RenderFrameDirector Ownership Split

RenderSystem owns platform frame execution: acquire/import the backbuffer, maintain swapchain and presentation lifecycle, prepare backend-owned renderer-frame resources, execute the graph or prepared submit path, and present. It may pass L2 frame facts and prepared-frame configuration into renderer-owned contracts, but it must not branch on scene-runtime payload types or call legacy pipeline composition directly for custom graph composition.

Unmarked fallback requests fail deterministically at the director boundary. Renderer frame files stay backend-neutral and expose renderer/RHI concepts rather than Vulkan, Metal, WebGPU, Android, or iOS handles.

director decisions carry generic prepared renderer-frame requirements: renderer frame plan desc, bridge settings, expected draw counts, shader artifact root policy, max draw command policy, and native-handle/backend-branching boundary status. Vulkan can lower a prepared decision to the backend-owned prepared submit path after explicit `prepareRendererFrame`; WebGPU currently reports deterministic diagnostic-only behavior for unsupported prepared execution.

This split is Contract Complete or Prototype Complete according to the specific contract evidence. backend/platform/production status is not promoted by contract evidence; Backend Validated requires named backend smoke evidence, Platform Validated requires target lifecycle/runtime evidence, and Production Ready remains blocked by the broader migration, telemetry, lifetime, visual, and external platform matrix.

## Layer Boundary

- L2 owns engine GPU objects, validation, descriptors, command recording, push constants, frame slots, and portable resource state contracts.
- The semantics layer owns native capability interpretation, backend allocation intent, descriptor translation, pipeline compilation policy, synchronization lowering, surface acquire rules, and present semantics.
- The semantics layer exposes backend-native potential through capabilities and policy data instead of flattening features to the lowest common denominator.
- L2 chooses native, emulated, degraded, or diagnostic-fail behavior internally so renderer, GUI, samples, and FrameGraph do not branch on backend names.
- Renderer, GUI, samples, and FrameGraph do not include Vulkan, Metal, WebGPU, Android, or iOS native graphics headers.

## Frame Pipeline: Plan, Decision, Lowering

This section traces the full per-frame chain from frame acquire to GPU command submission, showing how L2 capability decisions flow from device init through FrameGraph compilation to backend execution.

### Device Init: L2 Decision Chain (runs once)

At device creation, each backend constructs a `NativeBackendCapabilityContract` (a static per-backend native feature list) and runs `chooseFeatureFallback` for each `EngineFeature`. The decisions are aggregated into an `EngineFallbackPlan` and applied to `DeviceCapabilities` via `plan.applyTo(caps)`, producing boolean capability fields in `caps.features.*`.

```
NativeBackendCapabilityContract(backend)
    → chooseFeatureFallback(contract, feature)   → NATIVE / EMULATED / DEGRADED / FAIL
    → buildNativeEngineFallbackPlan(contract, requirements)
    → plan.applyTo(caps)
    → caps.features.*  (boolean capability gates, cached for all subsequent frames)
```

Call sites: `vulkan_device.cpp`, `metal_device.cpp`, `webgpu_device.cpp`, `null_backend.cpp` — each in its `capabilities()` override. This runs once at device init, not per frame.

`applyTo` maps `Degraded` and `DiagnosticFailure` to `false`; `Native` and `Emulated` to `true`. Features with a meaningful topology-only degraded path may also expose a detail such as `subpassInputAttachmentDegraded`, so a false primary capability is not mistaken for permission to reinterpret an executable shader resource.

### Per-Frame Chain

```
Platform:  acquireFrame() → renderGraphFrame() → presentFrame()

Renderer:  RenderFrameDirector::compose()
             payload adapters (scene/particle/gui/postprocess) → RenderFrameIntent
             pass providers → RenderPassDeclaration list
             recordPassDeclaration() → FrameGraph passes (read/write + execute callback)
           ↓
           FrameGraph::compile()
             ① lowerSubpassGraph()     — reads subpassInputLoweringContract(caps)
                NATIVE   → single multi-subpass PassRecord (Vulkan, Null)
                DEGRADED → split into separate PassRecords (Metal, WebGPU)
             ② FrameGraphCompiler::compile()
                validate → cull (fixed-point) → resource lifetimes → barrier plan
                → alias plan               — reads caps.features.transientAliasing
                   NATIVE   → compute alias groups (lifetime + key + overlap)
                   DEGRADED → skip, aliasPlan is empty
           ↓
           CompiledFrameGraph
             pass order + barrier batches + aliasPlan + load/store + external resources
           ↓
           allocateTransientTextures(compiled)
             aliasPlan empty    → resourcePool_->acquireTexture() (pool recycling)
             aliasPlan non-empty → createMemoryHeap() per group + createPlacedTexture()
             (no capability gate — purely driven by compiled aliasPlan)
           ↓
           FrameGraphExecutor::execute(compiled)
             createCommandEncoder() → iterate executionOrder:
               replayPassBarriers()  (from compiled.passBarrierBatches_, not live state)
               beginRenderPass() → subpass: nextSubpass(); regular: callback
               callback = compose()-registered lambda (particle/gui/scene recordPass)
             queue->submit()

Backend:   RHI virtual dispatch → vulkan_native_graphics_commands / webgpu_backend_commands
           (no backend enum branch — backend differences resolved at compile time via caps)
```

### L2 Decision Consumption Points

L2 decisions are consumed at **compile time**, not at execution time. The executor (`allocateTransientTextures`, `FrameGraphExecutor`) reads no capability fields — it is purely driven by the `CompiledFrameGraph`.

| Consumption point | Capability field | NATIVE behavior | DEGRADED behavior |
|---|---|---|---|
| `lowerSubpassGraph` | `subpassInputLoweringContract(caps)` | Multi-subpass PassRecord | Split into separate PassRecords plus sampled-texture/current-fragment contract |
| `FrameGraphCompiler` (alias plan) | `features.transientAliasing` | Compute alias groups | Skip — empty aliasPlan |

When a backend is DEGRADED for a feature, the compiler produces a different compiled graph structure. The executor sees only the compiled result and needs no runtime capability check. This is the core design principle: **L2 decisions shape the compiled graph; the executor is capability-blind.**

### Key Design Rules

- **Renderer does not branch on `device_.backend()`.** Backend identity is known only in the backend layer and the deployment/selection layer. The renderer consumes `caps.features.*` booleans.
- **`caps.features.*` (L2 decision output) is not `caps.memory.*` (raw hardware fact).** For `transientAliasing`, Metal has `memory.transientAliasing = true` (MTLHeap exists) but `features.transientAliasing = false` (semantics plan says DEGRADED). The renderer must read `features.`, not `memory.`.
- **Executor has no capability gate.** `allocateTransientTextures` is driven entirely by `compiled.aliasPlan()`. An empty alias plan means pool allocation; a non-empty plan means heap+placed. The compiler is the single decision point.
- **Backend differences are resolved via RHI virtual dispatch.** Push constant emulation, depth texture binding, barrier recording — all handled inside backend implementations. The renderer sees only `GpuDevice` virtual interfaces and `caps.features.*` booleans.

## Depth-Only Shadow Pass Contract

Status: Contract Complete as of 2026-05-20. Backend Validated is claimed only for the local Windows/MinGW Vulkan Character Viewer hidden and visible stylized real-shadow smoke path completed on 2026-05-20. Metal, WebGPU, Android, iOS, hardware driver validation, visual parity, Platform Validated, and Production Ready are not claimed for the real shadow-depth path.

The L2 shadow-depth contract models a depth-only render pipeline and render pass as engine concepts, not as Vulkan, Metal, or WebGPU API shapes. A depth-only `RenderPipelineDesc` has no color targets, uses an explicit depth/stencil format such as `D32Float`, and requires explicit depth test and depth write state. Cull mode, front-face winding, depth bias intent, viewport, scissor, depth load/store, and attachment clear/load behavior must come from L2 descriptors or command state. Backend default state must not decide any visible shadow behavior.

The lowering contract maps the same L2 state for every backend target. Null validates the depth-only pipeline and pass shape, including rejection of non-depth formats for depth/stencil attachments. Vulkan lowers the pass to zero color attachments with an explicit depth attachment, render pass clear/load/store state, and pipeline depth/stencil state. Metal lowers the same contract to a color-less depth render pass and depth-enabled pipeline state. WebGPU lowers it to a render pass with `colorAttachmentCount = 0` and an explicit depth/stencil attachment. Unsupported or incomplete state must fail deterministically with diagnostics instead of being filled by backend-native defaults.

RenderGraph and PiKa stylized shadow composition use the same contract for `CsmShadow` and `CharacterShadow`. When caster inputs and callbacks are present, the graph records non-empty depth-only shadow passes. When caster inputs are absent, the pass is an explicit deterministic no-op and reports diagnostics such as missing shadow caster inputs rather than silently pretending that real shadow data exists. This is a contract boundary only; native runtime, platform lifecycle, visual parity, and production-readiness evidence remain pending in later phases.

## Native-First Semantics

The semantics layer reports and preserves backend-native potential. Vulkan may expose native push constants, descriptor indexing, secondary command buffers, timeline synchronization, queue families, and explicit memory control. Metal may expose argument buffers, tile memory behavior, indirect command buffers when validated, and Apple memory/storage modes. WebGPU may expose browser/runtime limits and validated optional features without pretending to match Vulkan. The semantics layer does not flatten these capabilities to a lowest common denominator.

The Vulkan semantics layer path starts from a native device capability snapshot owned by the RHI Vulkan runtime. The current bridge derives push constant limits, queue family count, secondary command-buffer availability, explicit memory-model facts, descriptor indexing support, and timeline synchronization support from RHI-owned Vulkan runtime inspection. Descriptor indexing and timeline synchronization are queried through the `vkGetPhysicalDeviceFeatures2` / Vulkan 1.2 feature chain and are promoted only when the native device reports support.

The current Vulkan backend validation contract aggregates semantics layer resource, descriptor, pipeline-layout, command, synchronization, and swapchain image policy lowering into one backend validation report. It verifies native push constants, descriptor indexing, secondary command buffers, timeline synchronization, explicit memory control, queue-family facts, barrier semantics, and two logical L2 frame slots even when the native swapchain image count is larger. The report carries only semantic lowering decisions and sanitized counts; it does not include Vulkan headers, `Vk*` handles, or native handles visible to upper layers.

The current Metal backend validation contract aggregates semantics layer resource, descriptor, pipeline-layout, command, synchronization, and iOS drawable lifecycle lowering into one semantic report. It verifies argument-buffer style descriptor binding, push constant upload-buffer emulation, private/shared/managed/memoryless storage-mode mapping, indirect command-buffer selection, command-buffer completion, drawable present semantics, background/foreground/layer-resize lifecycle handling, two logical L2 frame slots, and native-handle leak rejection. This is Contract Complete coverage on MinGW; native Apple runtime and hardware validation remain pending before Metal or iOS can be marked Platform Validated.

## Web-First Runtime Profile

WebGPU is a first-class RHI backend profile, not a lowest-common-denominator compatibility mode. The web runtime profile records WGSL as the shader target, browser canvas surface requirements, descriptor-to-bind-group lowering, push constant emulation, the currently fail-closed soft-secondary/render-bundle boundary, optional compute/storage promotion, and the two-logical-frame swapchain contract.

This matters for AI-era distribution: browser delivery, generated content previews, cloud-assisted tools, and lightweight shareable runtimes need deterministic WebGPU contracts. The RHI must expose web capability facts and diagnostics internally while keeping renderer, FrameGraph, GUI, samples, and gameplay code backend-neutral.

Compute dispatch and storage texture binding are first-class engine features. WebGPU promotes them only when the runtime profile reports validated native support. Missing compute or storage texture support becomes deterministic diagnostic failure for compute frame requirements, while descriptor-table pressure may degrade to a bounded bind-group cache when correctness is preserved.

Transient render-target aliasing is performance-only for WebGPU browser deployments. When renderer or FrameGraph plans declare it as a performance hint, the semantics-layer WebGPU fallback policy degrades it deterministically and requires telemetry instead of blocking frame startup.

The current WebGPU runtime capability bridge converts the L2 runtime profile into a semantics-layer native capability contract. Browser-only profiles expose runtime limits and optional feature metadata without promoting compute/storage. Platform-validated profiles promote compute dispatch and storage texture binding into native feature facts, allowing the same semantics-to-L2 fallback bridge used by FrameGraph to produce backend-aware plans from real browser capability data.

The current WebGPU FrameGraph runtime bridge consumes a `WebGpuRuntimeProfile` and an `RhiFramePlan` directly. It produces the same hidden-backend L2 fallback plan while merging runtime-profile diagnostics, so Web deployments have a single tested path from browser capability probing to FrameGraph feature requirements.

The current WebGPU canvas lifecycle bridge converts a runtime profile into WebCanvas lifecycle state and lowers resize, surface lost, surface recreated, and memory warning events through the same semantics layer platform lifecycle contract used by native surfaces. Canvas resize reconfigures the surface, surface loss stops acquire/present and releases surface-scoped frame resources, and invalid profiles propagate canvas diagnostics without exposing browser or native handles upward.

The current WebGPU runtime telemetry collector aggregates the runtime profile, FrameGraph/fallback plan, and canvas lifecycle lowering decision into one bounded report for browser deployments. It records native/emulated/CPU replay/degraded feature counts, diagnostic failure counts, lifecycle rebuild/release flags, double-buffer state, and capacity-exhaustion diagnostics while preserving the rule that backend fallback details and native handles stay hidden from upper layers. Feature and diagnostic counters use checked addition so telemetry reports fail deterministically instead of wrapping when repeated fallback plans would overflow accounting.

The current WebGPU deployment readiness gate consumes that telemetry report and produces a browser deployment decision: Contract Complete, Platform Validated, or Diagnostic Failure. The decision exposes whether a frame can start, whether a swapchain rebuild or resource release is pending, whether telemetry is required for degraded-but-correct paths, and whether any hidden-backend or native-handle boundary rule was violated.

The current WebGPU FrameGraph deployment bridge composes the profile, frame plan, canvas lifecycle event, fallback plan, telemetry report, and readiness gate into one tested path. This gives renderer and FrameGraph migration a web-first integration point without branching on WebGPU limitations or native platform details above the semantics layer.

The smoke covers runtime/native device probing, compute/storage promotion, live canvas resize, surface loss and recreation, memory-warning diagnostics, two logical frame slots, frame-start begin/skip decisions, and a browser-observable compute smoke after lifecycle handling. ## Automatic L2 Fallback

L2 receives engine-level requests and selects one of four internal paths: native, emulated, degraded, or diagnostic failure. Native and emulated paths are invisible to upper layers. Degraded paths must be deterministic and reported through telemetry. Diagnostic failure is required when resource semantics are unknown or when fallback would change correctness.

The current semantics layer policy bridge consumes `NativeBackendCapabilityContract` instead of hard-coding backend names in upper layers. Vulkan native facts can select native push constants, native secondary command buffers, native descriptor indexing, timeline synchronization, and explicit memory control. If Vulkan lacks descriptor indexing, descriptor tables degrade deterministically to bounded descriptor lowering. WebGPU push constants are emulated internally; WebGPU soft secondary command buffers remain `DiagnosticFailure` until an executable native lowering exists. CPU replay is not a WebGPU production capability or acceptance path.

The current L2 fallback planner consumes those feature decisions and owns upper-layer visibility. Native, emulated, and CPU replay paths remain hidden from renderer, GUI, samples, and FrameGraph. Degraded paths require deterministic telemetry. Any degraded path that would change correctness becomes diagnostic failure before work is recorded. Planner decision capacity is bounded by contract, and oversized capacities become deterministic planning failures instead of implicit large allocations.

The current semantics-to-L2 fallback bridge accepts engine feature requirements, queries backend-native capability facts, chooses per-feature native/emulated/degraded/diagnostic decisions, and builds one L2 fallback plan. This bridge is the intended integration path for renderer and FrameGraph migration: upper layers declare requirements, while backend and platform branching stays inside RHI.

## Descriptor Model

The public L2 binding vocabulary is Descriptor-based. WebGPU bind groups, Metal argument binding, and Vulkan descriptor sets are backend mapping targets only.

- DescriptorLayout describes a named binding layout with binding slots, descriptor types, shader visibility, and array/table shape.
- DescriptorSet owns one concrete resource binding group.
- DescriptorTable represents large arrays or bindless-style descriptor ranges when backend capabilities allow it.
- DescriptorArena owns allocation and frame-local recycling policy.
- PipelineLayout declares a descriptor-layout registry, descriptor set slots, descriptor table slots, and push constant ranges.

Descriptor arenas are capacity-bounded objects. Allocation failure is deterministic and returns diagnostics instead of silently expanding in frame hot paths. Descriptor capacity accounting rejects arithmetic overflow before consuming arena capacity. Arena reset starts a new allocation generation; descriptor sets and tables allocated before reset are stale and must reject further writes and pass binding. Backends may lower arenas to Vulkan descriptor pools, Metal argument-buffer allocation, WebGPU bind group caches, or Null recording, but renderer and FrameGraph code see only descriptor allocation results, deterministic stale-allocation diagnostics, and arena statistics.

DescriptorSet is now a public L2 object, not just an allocation counter. Descriptor sets expose their named layout, allocation metadata, current-allocation lifecycle state, bounded write stats scoped to the current allocation generation, read-only binding-written queries, sanitized resource-object binding writes, and deterministic validation for written binding resources. DescriptorTable is also a public L2 object for large indexed descriptor ranges. Tables are arena-allocated with explicit non-empty label, capacity, shader visibility, descriptor type, current-allocation lifecycle state, indexed writes, read-only index-written queries, write stats scoped to the current allocation generation, deterministic validation for written descriptor resources, and deterministic allocation/capacity diagnostics. PipelineLayout can declare descriptor table slots beside descriptor set slots, and render/compute passes bind DescriptorTable objects through the same L2 command vocabulary. TextureView and Sampler are also public L2 objects so sampled-texture and sampler descriptors bind engine objects instead of backend handles. Descriptor writes carry an explicit resource kind, so L2 can reject buffer/texture-view/sampler mismatches deterministically instead of guessing from IDs or backend state. The Null backend validates descriptor layout names, descriptor table labels, binding existence, descriptor type matching, descriptor table slot-name matching, table index capacity, resource-kind matching, registered resource IDs, buffer/texture/sampler object class, buffer usage for uniform/storage descriptors, texture usage for sampled/storage texture descriptors, stale descriptor allocation state before pass binding, pass-level descriptor set/table compatibility with the currently bound PipelineLayout, draw/dispatch descriptor completeness against the current pipeline shader reflection and pass stage, required DescriptorSet binding writes, required DescriptorTable index writes, current resource registry validity for written descriptor content before draw/dispatch, hidden backend fallback details, and no native-handle exposure.

The current semantics layer descriptor-lowering contract maps DescriptorLayout and DescriptorArena data to backend semantics without changing the public vocabulary. Vulkan lowering targets descriptor set layouts and descriptor pools. Metal lowering targets argument-buffer style argument bindings. WebGPU lowering targets bind group layouts and backend-owned bind group caches internally, while L2 and upper layers continue to use Descriptor terms. Descriptor tables may remain native when Vulkan descriptor indexing is available; otherwise they degrade deterministically to bounded descriptor capacity.

## Resource And Memory Model

L2 owns stable GPU resource objects for buffers, textures, texture views, and samplers. Resource descriptors carry explicit usage flags and memory intent: GPU-only, CPU-to-GPU upload, GPU-to-CPU readback, or transient. L2 exposes resource IDs, sanitized allocation metadata, and memory statistics without exposing native handles. Resource memory accounting rejects byte-count overflow before object creation so reported allocation statistics remain deterministic, and texture size estimation rejects dimension/product overflow before resource registration.

Buffers and textures carry an explicit L2 resource state. CommandEncoder records buffer and texture transitions with typed barrier results, validates that the requested `before` state matches the current resource state, rejects no-op or mismatched transitions deterministically, and updates the tracked state only on success. Null resources maintain this state directly, so contract tests can verify barrier behavior without backend-native handles.

Null also maintains an internal resource registry for Descriptor writes and command-time descriptor validation. The registry records resource object kind, declared usage, and TextureView parent texture relationships at creation time, and unregisters resources on destruction. Descriptor writes fail deterministically when the resource ID is unknown, when a TextureView parent texture has already been destroyed, or when the declared usage does not satisfy the descriptor type, such as a storage buffer bound to a uniform-buffer descriptor or a storage-only texture view bound to a sampled-texture descriptor. DescriptorSet and DescriptorTable objects store only sanitized resource ID/kind records; draw/dispatch validation rechecks those records against the registry so resources destroyed after descriptor write cannot be used silently.

Backend-specific memory classes are translated internally. Vulkan can use device-local, host-visible, and transient allocation policies; Metal can map to storage modes and heaps when validated; WebGPU can map to usage flags and buffer mapping limits. If a backend cannot honor an intent exactly, L2 chooses native, emulated, degraded, or diagnostic failure according to the fallback policy and keeps the decision out of renderer-facing code.

The current semantics layer resource-lowering contract records backend-native semantics without including native graphics headers. Vulkan lowering maps buffer and image usage to descriptor-safe native intent such as device-local memory, host-visible readback/upload memory, transfer usage, color attachment usage, sampled usage, and transient aliasing memory when explicit memory control is available. Metal lowering maps memory intent to private, shared, managed, or memoryless/transient storage semantics and maps usage to buffer or texture access roles. WebGPU lowering maps resource usage to buffer and texture usage roles, treats GPU-only resources as native, uses queue-write/upload emulation for CPU-to-GPU memory intent, and degrades transient texture memory intent because WebGPU does not expose Vulkan-style transient aliasing. Null lowering records resources deterministically for validation and memory accounting. All paths keep native handles hidden from upper layers and carry a fallback mode of native, emulated, degraded, or diagnostic failure.

## Frame Resource Lifetime

L2 owns frame-local resource lifetime policy. Deferred destruction, transient render targets, upload blocks, descriptor allocations, command buffers, swapchain images, and surface-scoped resources are indexed by the two logical frame slots. A resource last used by frame serial `N` is not released until serial `N + 2` is complete. Deferred-destroy registration rejects retire-serial arithmetic overflow before enqueueing the resource.

Frame resource queues are capacity bounded. Oversized recycler capacities fail deterministically before operations can enqueue records, and the queue stats remain empty for invalid configurations. Exhaustion, queued byte accounting overflow, retire-serial overflow, and released-byte accounting overflow return deterministic diagnostics instead of silently allocating or wrapping statistics in a frame hot path. Surface lifecycle events may release surface-scoped resources immediately, while memory warning paths release transient resources and request memory-budget refresh. Native handles remain hidden from renderer, GUI, samples, and FrameGraph.

## Push Constants

Push constants are a first-class command feature. Vulkan maps to native push constants. Metal maps to native small constant APIs or backend-owned constant storage. WebGPU maps to a backend-owned system descriptor plus upload ring. Null records and validates the contract.

Pipeline layout lowering keeps push constants separate from descriptors. Vulkan lowering emits native pipeline layout semantics with descriptor set layouts and native push constant ranges, and fails deterministically when requested push constant bytes exceed the native device limit. Metal lowering keeps argument binding layout semantics and uses an emulated upload buffer for push constant data. WebGPU lowering keeps bind group layout semantics and adds a backend-owned system bind group plus upload ring for push constant emulation. L2 rejects push constant layout ranges and command updates whose `offset + size` overflows, and rejects ranges that overlap for the same shader stage, while allowing different stages to share byte ranges when explicitly declared. Null lowering records the pipeline layout contract for validation.

PipelineLayout, RenderPipeline, and ComputePipeline are public L2 objects. Shader entrypoints reference Slang source modules and entrypoint names; SPIR-V, MSL, WGSL, and reflection products are backend/build artifacts and are not modeled as renderer-facing shader source. The current L2 shader package contract requires a Slang module, generated SPIR-V artifact, generated MSL artifact, generated reflection metadata, explicit entrypoints, reflection descriptor bindings, hidden backend fallback details, and no native-handle exposure. PipelineLayout can carry the DescriptorLayout registry used by descriptor-set slots, allowing L2 to match pipeline-used reflection bindings against descriptor binding index, descriptor type, shader-stage visibility, and DescriptorTable capacity before backend lowering. Null exposes typed render/compute pipeline validation reports with entrypoint counts, stage-filtered descriptor binding counts, descriptor layout/set/table counts, push constant bytes, shader-package validation state, reflection matching state, hidden-fallback state, native-handle boundary state, and deterministic diagnostics. Null pipeline creation reuses that report and only creates objects after the typed validation succeeds. Created RenderPipeline and ComputePipeline objects persist a read-only stage-filtered copy of their shader reflection metadata plus the validation report, so later command validation can reason from the actual pipeline object instead of external ShaderPackage lifetime, unrelated package entrypoints, or backend handles. Null render and compute passes also validate push constant updates against the currently bound PipelineLayout, requiring a bound pipeline, non-empty stage visibility, pass-compatible shader stages, overflow-free offset-plus-size, and a push constant range that fully covers the requested offset and size.

The current semantics layer shader package lowering contract maps the same L2 package into backend semantics without exposing native shader handles. Vulkan consumes SPIR-V artifacts plus reflection metadata and validates native push constant limits. Metal consumes MSL artifacts and function entrypoints. WebGPU records an internal Slang-to-WGSL translation path plus bind-group and push-constant-emulation reflection metadata. Null records the package for deterministic validation. The lowering path can consume an explicit descriptor-layout registry and then requires each reflected descriptor-set binding to match the PipelineLayout slot, DescriptorLayout binding index, descriptor type, and shader-stage visibility, and each reflected DescriptorTable index to fit the declared table capacity. Missing artifacts, native-handle exposure, push constant overflow, missing descriptor metadata, out-of-capacity descriptor table reflection, or reflection bindings that do not match declared PipelineLayout/DescriptorLayout metadata become diagnostic failures before backend work is recorded.

## Command Model

L2 uses command encoders and typed pass encoders. Render, compute, and transfer commands are recorded through separate pass scopes. Soft secondary command buffers are part of L2; Vulkan can lower them to native secondary command buffers. WebGPU render bundles and soft-secondary execution remain separate contracts and must fail closed until the RHI exposes an executable end-to-end mapping.

The current semantics layer command-lowering contract records command workload intent without exposing native command handles. Vulkan primary work lowers to primary command-buffer semantics, soft secondary command buffers lower to native secondary command buffers when the backend reports support, and push constants stay native. Metal command work lowers to command buffer/render encoder semantics; soft secondary work uses indirect command buffers when available and otherwise CPU replay. WebGPU render-bundle semantics are recorded only for the explicit render-bundle intent; soft secondary command lowering is `DiagnosticFailure` until an executable native path exists. Null lowering records command buffers for validation.

The current L2 command API exposes render, compute, and transfer pass encoders, render bundles, and soft secondary command buffers. Render and compute passes can bind L2 pipeline objects, DescriptorSet objects, and DescriptorTable objects before recording work. Null command execution validates pipeline binding, descriptor arena lifecycle state at bind time, descriptor set slot/layout compatibility, descriptor table type/stage/capacity compatibility, descriptor completeness before draw/dispatch from the bound pipeline reflection rather than every PipelineLayout slot, required descriptor content writes, descriptor resource liveness from the current registry, push constant stage/range coverage, indexed draws, compute dispatch, transfer copies, render bundle encoder lifecycle, soft secondary encoder lifecycle, and soft secondary replay through deterministic command counts. Backend-native secondary command buffers remain a semantics-layer lowering choice; L2 presents one engine-facing secondary command buffer concept.

Command recording operations return typed L2 validation results where the caller needs diagnostics. The Null command encoder now tracks active pass scope, rejects resource transitions while a render/compute/transfer pass is open, rejects `finish()` with an unclosed pass, rejects repeated pass `end()`, and requires render and compute pipelines before draw or dispatch commands. These checks keep backend-specific encoder rules below L2 while giving upper layers deterministic failures instead of native API undefined behavior.

## FrameGraph Integration

FrameGraph builds an RHI frame plan with two-frame-slot validation, bounded pass and barrier records, and L2 feature requirements. Requirements describe engine needs such as push constants, soft secondary command buffers, descriptor tables, transient aliasing, and timeline synchronization. FrameGraph does not include semantics layer or backend-native headers and does not branch on backend names.

Renderer draw plans can be adapted into RHI frame plans through a renderer-facing bridge. The bridge records only engine semantics such as push constant usage, soft secondary command eligibility, descriptor-table pressure, transient targets, compute dispatch, and storage texture binding. It produces bounded `RhiFramePlan` requirements without exposing native handles or requiring backend-specific branching in renderer code.

Renderer frame plans can aggregate multiple renderer passes into a single RHI frame plan. Scene, GUI, postprocess, particles, and compute-style renderer passes share the same two-slot frame contract, pass capacity, and feature requirement capacity. Duplicate feature requirements are collapsed at the frame level before the plan enters semantics-layer WebGPU readiness evaluation, so repeated push-constant use across several passes does not inflate fallback accounting.

Renderer-facing RHI frame plan construction should use the bounded builder path in production code. The builder reserves a fixed draw-plan capacity up front, rejects pass overflow deterministically, validates double-buffer frame slots, and returns diagnostics instead of relying on unbounded frame-time growth.

## Double-Buffered Swapchain

The swapchain contract uses two logical frame slots and requests two images. If a platform requires more native buffering, L2 still exposes only two frames in flight and emits diagnostics about the native/platform difference. Frame-local descriptor arenas, upload rings, command pools, deferred destruction, and transient resources are indexed by `frameSerial % 2`.

Swapchain lifecycle is exposed through backend-neutral L2 state changes instead of native surface handles. Surface loss or pause disables acquire/present and releases in-flight double-buffer slots. Surface restoration reports acquire/present readiness plus swapchain rebuild intent. Resize validates non-zero extent, clears in-flight slots, requests surface-resource release, and reports rebuild intent. Presenting an old frame after surface loss fails deterministically with surface diagnostics.

For Vulkan, semantics layer respects native `minImageCount` and `maxImageCount` constraints. If the surface requires more than two images, semantics layer creates the native swapchain with the required image count while L2 keeps two logical frame slots. If a constrained platform supports fewer than two native images, L2 reports a deterministic diagnostic and reduces logical frame slots to the native limit.

The current Vulkan swapchain lowering delegates native image-count selection to the same semantics layer policy. This keeps hidden-window Vulkan smoke coverage aligned with the RHI double-buffer contract while renderer-facing code stays backend-neutral.

## Synchronization Model

L2 owns queue submit, acquire, present, and frame-slot synchronization contracts. Upper layers do not receive native semaphores, fences, shared events, or browser promises, and upper layers are not required to perform blocking waits.

Queue submit and swapchain present return typed L2 result objects with diagnostics and submitted/presented frame metadata. Null submit reports submitted command counts. Null present validates the two-slot frame index, in-flight state, and frame success before releasing the slot, so present failures are deterministic instead of silent.

The current semantics layer synchronization-lowering contract maps Vulkan work to queue submit, timeline semaphore, acquire semaphore, present queue, and double-buffer frame-slot semantics when native timeline synchronization is available. Limited Vulkan devices emulate timeline progress with frame-retire fences internally. Metal uses command-buffer completion, drawable present, and frame-slot serial semantics. WebGPU uses queue submit, submitted-work completion, surface present, and frame-slot serial semantics. Null records synchronization for validation.

## Mobile Lifecycle

Android pause stops acquire and present, releases swapchain images and per-surface frame resources, and rebuilds double-buffer swapchain state on resume with a valid surface.

The current Android surface lifecycle bridge validates that an active surface starts with acquire/present allowed, pause blocks both operations and releases surface resources, surface loss invalidates the swapchain and keeps acquire/present blocked, resume refreshes memory budget state while waiting for a valid surface, surface recreation restores acquire/present and requests swapchain rebuild, memory warning refreshes budget state and releases transient resources, and every transition preserves two logical frame slots. The report carries only lifecycle decisions, sanitized flags, and diagnostics; it does not expose `ANativeWindow`, JNI, Vulkan handles, or native surface objects to upper layers.

iOS backgrounding stops drawable acquire. Resume or layer resize rebuilds drawable-backed resources while preserving the L2 two-frame-slot contract.

The current iOS layer lifecycle bridge validates that an active layer starts with drawable acquire/present allowed, background blocks both operations, memory warnings request transient release and memory-budget refresh, foreground rebuilds drawable-backed resources, layer resize requests drawable rebuild, layer loss releases surface-scoped frame resources, layer recreation restores acquire/present, and every transition preserves two logical frame slots. The report is semantic and contains only semantics layer lifecycle decisions, sanitized flags, and diagnostics; it does not expose UIKit, CoreAnimation, Metal, or native layer handles.

## Platform Lifecycle Lowering

semantics layer models platform lifecycle as semantic surface events rather than native handles.
