# ARP Editor 3D Viewport Render Contract

Status: `Prototype Complete` for the Vulkan pass-recording smoke; production scene execution and UI composition are not implemented. This contract does not claim `Backend Validated`, `Platform Validated`, or `Production Ready`.

## Frame input

`editor/SceneViewportFrame` version 2 identifies a scene and committed editor state version, the resolved camera GameObject, a target extent, an in-bounds physical-pixel viewport rectangle, and ordered draw items. Each draw item carries stable GameObject and component IDs, the traversal snapshot's world-space TRS, and authored mesh and material resource IDs. Camera data includes its world-space TRS, row-major view/projection matrices, and the aspect policy and ratio used to build the projection. It never carries an RHI/native handle, pointer, OS window coordinate, or backend enum.

`buildEditorSceneViewportFrame` consumes the engine `SceneTraversalSnapshot`, resolves the active camera through `CameraResolver`, and copies enabled `MeshComponent` authored resource identities with each node's world transform. For `MatchViewport`, it rebuilds the camera projection from the physical pixel rectangle's exact width/height ratio; `Fixed` preserves the authored camera aspect. CPU matrices use the repository `core::math` row-major contract. A frame with an invalid scene snapshot, absent/invalid camera, non-finite matrix or transform, invalid extent/rect, viewport-aspect mismatch, missing object/component identity, or empty mesh/material resource ID fails with a stable diagnostic before resource lookup or command recording. Resource IDs are resolved through the owning asset/resource service; unresolved or ambiguous IDs fail. There is no default-mesh or default-material substitution in the production path.

## Target and ordering

`editor_scene_viewport_resource_resolver` resolves each authored draw item through generation-aware `ResourceManager::find<T>` handles. It requires a ready indexed mesh with valid CPU geometry, a ready `MaterialResource`, a ready typed source resource, a ready `ShaderPackageResource`, and non-empty Slang/SPIR-V/MSL/reflection artifact references. It validates the material contract and shader interface before returning CPU authoring values, stable IDs, generations and mesh counts; handles do not escape. Failures are deterministic per-item diagnostics. This remains CPU-side resolution only: it creates no renderer-owned GPU binding or draw payload.

The current surface schema is `arp/material/pbr-metallic-roughness` v1. It defines base-color and emissive factors, metallic and roughness factors, alpha mode/cutoff, double-sided state, and optional stable IDs for base-color, normal, metallic-roughness, occlusion, and emissive textures. All texture channels use the fixed sampler contract `magFilter=LINEAR`, `minFilter=LINEAR_MIPMAP_LINEAR`, `wrapS=REPEAT`, `wrapT=REPEAT`; no per-material sampler override is represented. The referenced `ShaderPackageResource` must declare the identical interface name and version. Version 0, unsupported surface models, invalid/non-finite factors, and interface mismatches fail closed. Material texture IDs participate in the resource dependency graph and each non-empty ID must resolve to a ready `TextureResource` during viewport resolution.

The editor's `mapGltfPbrMaterial` contract maps the glTF core metallic-roughness fields to PBR v1 only when the caller supplies a texture-resource-ID table exactly index-aligned with the imported document texture table and the imported material carries a completeness marker from the current parser. It accepts texture references only when their selected coordinate set is UV0 and the referenced glTF texture omits an explicit sampler; the renderer-facing sampler contract is not represented yet. It rejects out-of-range indices, non-UUID IDs, unsupported material extensions/fields, invalid factors and shader-interface mismatches. The GLB parser preserves all five PBR texture coordinate-set selectors, validates core factors, and rejects malformed fields or unknown alpha modes instead of defaulting them. Prefab runtime blob v1/v2 remains readable but has no completeness marker; those materials fail closed in the new mapper. Imported material texture indices are document-table indices (while `texCoord` chooses a mesh-local UV set); neither is itself an ARP resource ID. Unity's current `MaterialImporterAsset` lacks enough PBR factors and typed texture semantics to populate PBR v1, so the editor mapper does not accept it. The renderer runtime material descriptor still has no surface parameters, so this CPU mapping contract does not imply a GPU material implementation.

`EditorSceneViewportMeshCache` is the renderer-owned geometry lifetime boundary. It accepts only a successful resolver item, re-resolves the mesh by stable resource ID, checks the exact resource generation, immutable-geometry admission, and resolved counts, then uploads through `uploadMeshToRhi`. Cache identity is `(meshResourceId, meshGeneration)` and the cache binds to one `ResourceManager` and one `GpuDevice` on first successful upload; cross-owner use fails. Entry-count and resident-geometry-byte limits are mandatory constructor inputs; a miss that exceeds either limit fails with a stable diagnostic and does not evict potentially in-flight resources. Its owner must outlive submitted work using its buffers and be destroyed before the device. Cache tests use the Null device only for upload/cache API semantics; they do not prove native backend payloads or visible rendering.

`EditorSceneViewportTextureCache` is the renderer-owned sampled-texture boundary. It re-resolves each stable texture resource ID, requires the exact resolved generation and a decoded RGBA8 payload whose dimensions, byte count, color-space flag, usage, and alpha metadata agree, then creates an explicitly formatted sampled/copy-destination texture, sampled view, and backend-owned upload. Cache identity is `(textureResourceId, textureGeneration)`; the cache binds to one `ResourceManager` and one `GpuDevice` after the first successful upload. PBR v1 material bindings must request sRGB for base-color/emissive and linear for normal/metallic-roughness/occlusion; disagreement fails closed. The shared sampler spells out linear magnification, linear minification plus mip filtering, repeat on U/V and clamp on W, matching the current material contract. Entry-count and decoded base-level byte limits are mandatory; no automatic eviction is allowed while frames may retain bindings. A failed upload commits neither an entry nor a sampler, so a later device cannot inherit a sampler from a failed owner. The cache owner must outlive submitted work and be destroyed before its device. Current tests use Null for texture creation/upload/cache API semantics only; they do not prove native transfer execution, descriptor binding, or visible rendering.

`EditorSceneViewportMaterialShaderBindings` v1 validates the parsed `ShaderReflection` contract version and maps PBR v1 semantics by reflected names: `BaseColorTexture`, `NormalTexture`, `MetallicRoughnessTexture`, `OcclusionTexture`, `EmissiveTexture`, and the shared `LinearSampler`. Each must be a scalar Fragment-stage descriptor with the declared sampled-texture/sampler type, and no other logical descriptors are allowed in this editor material interface. The payload stores logical set/binding/count/stage values copied from reflection; it does not infer slot numbers or WebGPU/Metal physical slots. Missing or duplicate names, extra bindings, type/count/stage mismatches, or logical address collisions fail with stable diagnostics before texture cache acquisition. The six bindings are converted to RHI's `ShaderReflectionDesc`; a logical pipeline layout is assembled from those facts and checked by `validatePipelineLayoutAgainstShaderReflection`. This verifies the generic RHI descriptor contract only; it does not create a device pipeline/layout, write descriptors, or prove backend lowering. Reflection parsing is an explicit input to payload preparation; file loading and shader artifact freshness validation remain the package-loading owner's responsibility. Optional material texture values remain absent in the CPU payload, but this fixed shader interface still requires all five sampled-texture descriptors. `validateEditorSceneViewportDescriptorReadiness` reports `MissingTexture` and the first absent slot; a CPU-valid payload is not draw-ready until this check succeeds. The executor must not substitute a dummy descriptor. Supporting absent slots requires a versioned shader variant or an explicitly contracted neutral resource path with four-backend lowering evidence.

`recordEditorSceneViewportPass` records explicit color/depth transitions and attachments, clear/store operations, viewport/scissor, reflected material descriptor set, the 256-byte row-major push-constant ABI, vertex/index buffers, and one indexed draw per validated submesh. It requires an explicit draw-call budget, matching RGBA16Float/D32Float targets, sampleable color usage, and ready mesh/descriptor inputs. Vulkan is the only enabled executor backend; Null is validator-only and Metal/WebGPU fail with a stable unsupported-executor diagnostic. The hidden Vulkan smoke uses an explicitly named debug-triangle and uploaded white-texture fixture, submits one indexed draw, and waits for completion. The recorder is not yet fed from the editor scene snapshot/resource resolver, and the resulting target is not sampled by the UI viewport panel.

The graphics pipeline contract binds vertex layout, shader package/reflection, matrix push-constant layout, depth test/write, cull/front-face, topology, viewport, scissor, and color/depth formats explicitly. Pipeline and resource creation failure rejects the frame. Mesh/material resolution is renderer-owned and keyed from authored stable resource IDs; resolved handles never escape that owner.

## Backend disposition

| Backend | Current editor viewport disposition | Meaning |
| --- | --- | --- |
| Null | `ContractValidationOnly` | Validates frame semantics; it does not count as rendered geometry. |
| Vulkan | `DiagnosticFailure` for scene frames | The separate recorder smoke submits one fixture indexed draw. Scene-resource wiring and RenderDoc replay inspection of its offscreen color/depth event remain open, so the editor scene viewport is not `Backend Validated`. |
| Metal | `DiagnosticFailure` | `ARP-EDITOR-VIEWPORT-BACKEND-EXECUTOR-NOT-VALIDATED`; viewport execution is gated off. |
| WebGPU | `DiagnosticFailure` | Same stable diagnostic; viewport execution is gated off. |

These are editor integration results, not claims about general RHI graphics capability. An explicit `Prototype/Legacy` wireframe may remain during migration but cannot satisfy this contract or be reported as a backend fallback.

## Verification boundary

The quick contract tests cover viewport version, identity, target/rect bounds, row-major camera data, finite camera/object transforms, exact `MatchViewport` aspect, traversal-to-frame construction, mandatory authored resource bindings, successful typed metadata resolution, missing/declared/wrong-type mesh, invalid mesh data, missing source/shader dependencies, incomplete shader artifact metadata, PBR v1 serialization round-trip and validation, texture dependencies, rejected legacy/invalid material values, shader-interface mismatch, reflection-driven PBR descriptor mapping and its negative cases, all four backend dispositions, generation-keyed mesh-cache hit/staleness/budget behavior, and texture-cache upload/hit/staleness/color-space/owner/budget behavior. `arp_editor_viewport_pipeline_hidden_smoke` now proves real Windows/Vulkan fixture texture upload, pipeline/layout creation, six descriptor writes, color/depth pass recording, and one submitted indexed draw. RenderDoc capture `build/arp-editor-evidence/viewport-draw/editor-viewport-draw-validated_capture.rdc` was produced and its embedded backbuffer thumbnail inspected; qrenderdoc replay analysis did not produce a report, so the offscreen viewport color/depth output and replay diagnostics remain unverified. `Backend Validated` still requires scene snapshot/resource-resolver integration plus RenderDoc replay inspection of the viewport attachments and selected object's draw. Metal and WebGPU remain separately platform-unvalidated until native target smoke paths pass.
