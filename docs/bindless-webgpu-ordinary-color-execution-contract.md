## L2 intent and correspondence

OriginalExecution13 is an independent, explicitly opted-in Emulated Graphics
profile. Its primary indexed tables contain Fragment buffers only. Ordinary
scalar Vertex/Fragment bindings contain buffers, independent non-comparison
samplers and completed color textures. Texture inputs use authentic whole-upload
control1/Publication6 Sources: RGBA8 or RGBA16F, 2D, 2DArray or one square six-face
Cube. Selected entry reflection, original physical mappings, formats, dimensions,
buffer ranges and actual device limits must agree before recording.

An independent queried execution capability is required. Neither Preparation11,
Closure17, generic descriptor support nor compiler metadata grants Execution13.
OriginalExecution2 and every earlier profile retain their scope. Generic ordinary
image execution remains unavailable outside the explicit profile.

Closure18 is the execution correspondence companion of cold Closure17. It
consumes an executable Execution13 plan and reuses the same typed exporter,
physical group builder and ownership validation; Closure17 continues to accept
only nonexecuting Preparation11. Both retain the authentic Root2, authorization,
prepared binding, immutable descriptor Sources, native image/view/parent/sampler
owners and canonical inventory. A forged shared owner or stale publication must
fail without partial publication or quota retention.

## Original transaction and completion

Execution13 uses existing admission2/program2 and Lifecycle12, Content9 with
completed-read profile3, Read18/Pending9, and the existing public Root callback
executor. Its inputs are the original stream, graph, inventory, state transaction,
fault result and readback binding. No replacement executor, synthetic completion,
CPU replay, new resource identity or duplicate state journal is permitted.

Ordinary sampled transitions retain their actual declared stages. Completed
input stamps remain read-only; color attachment proposals publish only after
the original successful native completion and fault/map events. Cancellation,
recording or submission failure must leave input stamps and unpublished outputs
unchanged. Recorded or submitted resources stay alive until the real native
events drain, including caller drop and uncertain submission. Quotas and callback
reservations return through existing retirement.

Resource entries, native/CPU owners, attachments, command/visit counts and
submission/callback/result memory are preflighted against caller-authored budgets
and queried limits. Exact and one-less cases must be covered. Recording,
validation and submission retain existing zero-allocation hot-path requirements;
no shader compilation, I/O, blocking wait or unbounded growth is introduced.
