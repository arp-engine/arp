# Original Graphics Issuer8 private preparation candidate

This is the preparation-stage successor of the copied Issuer8 value/refusal
contract. It is not applied to live headers, backend sources or CMake while
Callback8's selected inputs await same-payload96 acceptance. Contract decisions
are tested before the actual backend translation unit is compiled against the
copied headers. Successful compilation is not native preparation validation.

Issuer8 consumes the exact Callback8/Command8/Cold8/Payload8/Freeze8/Closure10/
Lifecycle5/ContentPlan6 graph. Its existing wrapper, Recording and Submission
add three owners; seven receipts reuse the existing slots and original quota
domains. No new executor, facade, root, journal, pool, loss subscription or
receipt authority is introduced. A separately authored issuer workload must
declare the full owner demand before Source admission. The Callback-only252
workload is unchanged and must refuse issuer preparation at its old ceiling.

WebGPU preparation retains all existing checks: explicit opt-in, exact profile,
registered original custody, root liveness, matching quota identities and byte
limits, complete owner ceilings, one recording issuer, one submission issuer,
seven native receipt slots and a single sticky claim. Missing custody and bad
intent refuse before native preparation/allocation. Host builds additionally
reject native unavailability. Partial allocation or receipt preparation failure
must roll back without claiming or publishing. Publication occurs only after
all seven actual receipts and existing issuers have been prepared successfully.

The WebGPU8 preparation diagnostic is
`RHI-ORIGINAL-GRAPHICS-ISSUER-WEBGPU-RECORDING-MISSING`. Other initial Issuer8
diagnostics remain unchanged. Versions1–7 preserve their decisions;0/9, unknown
backends, mixed versions, malformed participants, overflow and budget failures
remain deterministic refusals. NativeExecution stays capped at7. Issuer
preparation grants no recording, draw, submission, shader output, GPU completion
or public BindlessCross authorization.

Copied acceptance requires assertion-enabled L2/four-backend and legacy tests,
the actual backend TU compiled using the configured MinGW and Emscripten
recipes, and linked Host rejection checks using that copied backend object.
The Wasm compiler must see the actual emdawnwebgpu headers/native branch; a
host stub compile cannot prove that. Depfiles must select the copied semantic
and frontend headers and retain the unchanged backend source identity.

Callback24 and frozen tools6 must match before and after all candidate work.
No shared input or original library is overwritten. Candidate evidence must
keep preparation runtime, execution, public, platform, SDK-provenance and
production gates false until corresponding independent evidence exists.

and register the verified L2/preparation changes and build the original target.
