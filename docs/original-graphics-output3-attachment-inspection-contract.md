This extends the existing OutputSnapshot/3 frontend contract with a read-only,
bounded preflight over authentic original owners. It adds no resource owner,
allocation, state transaction, native API or execution grant. It is prepared-state
inspection only; native creation, recording, submission, completion, readback and
retirement remain separate. Existing OutputSnapshot1/2 paths are unchanged.

Before backend association may be added, inspection must prove:

- Explicit Output3 intent and StateBoundUsage6 opt-in, valid existing budgets.
- Authentic original root, exact ContentPlan6/finite Graphics profile, Prepared
  status and empty journal. The stream must be the same shared owner retained by
  that root's plan, not merely another stream over the same Inputs/graph.
- Authentic original output lease, same source metadata quota domain and ceiling,
  the existing exact Rgba16Float RenderAttachment|CopySrc target role/range.
- Existing state-bound usage projection is fully validated and bounded. Charge
  original commands and each emitted contribution against maxJoinVisits before
  the visit can consume its slot; do not increase existing workload budgets.
- Exactly one projected color attachment uses a view retaining that same output
  parent owner. Its immutable RenderPassArguments names the same view/format,
  Clear/Store operations, no resolve/depth/subpasses/layering; exact color range,
  ColorAttachment state, ColorAttachmentOutput stage, read|write access, and
  current parent registration generation are required.
- No candidate capture escapes on any failure: publish the borrowed attachment
  point to the caller only after whole inspection succeeds. Caller-supplied
  allocation bytes are budget inputs, never proof of native allocation/ownership.

The original root compares the retained Graphics stream by shared-owner identity
and validates its existing plan. No new persisted field or object layout changes.
The inspector consumes the existing OriginalTypedUsageProjection visitor and
texture/view/pass contracts; it does not invent descriptor provenance for an
attachment or reuse the Compute storage write proof.
