`OrdinaryDepthDomain/1` describes scalar ordinary `DepthTexture2D` and independent
comparison-sampler declarations. Selected Fragment or Compute entries are
inspected separately; a union declaration does not authorize a union entry.
Vertex, arrays, Cube/3D depth, dynamic offsets and table-backed declarations

nor proves sampling equivalence. Both declarations must be queried from the same
authenticated package, Root and selected entry. Existing ordinary opaque query
fixtures exercise that join for actual selected Fragment and Compute metadata.

`ContentPlan18` is an independent composition schema. It embeds the existing
Content9 color/attachment budget and adds bounded completed-depth controls,
cells and read steps. Color control3 may use existing RGBA8/Read8 or HDR/Read17;
canonical color control1 refuses in this native-depth schema. Depth controls
must be original Source6/Input3/control4 with completed, nonzero-generation and
nonzero-revision observations and no content mutation. The first native depth
source observes one D32 cell per distinct control. The actual content traversal
must deduplicate controls using the existing inventory and owner identity.

Depth reads use explicit ShaderRead/FragmentShader/ShaderRead intent. The
native Source2/control4 texture is a sampled single-mip, single-layer,
single-sample D32 2D view. Resource extents come from the actual texture, not
fixed scene dimensions. Sampled depth and every output attachment must have
independent registered resource identities. The existing graph proves barriers
and visibility; these content checks cannot synthesize transitions or hazards.

Color/attachment and depth inspector visits share the authored command and
projection ceilings. Each actual traversal is charged once; capacities use
subtraction to reject overflow. Depth count admission requires every retained
control to have a cell and at least one actual read. Failure must occur before
publishing a state/content proposal, consuming a unique descriptor, or claiming
a native submission. No second resource registry, state timeline or completion
serial is introduced.

The original transaction retains and revalidates the same physical

prepared Graphics binding, inventory and selected entry. Read-only depth cells
